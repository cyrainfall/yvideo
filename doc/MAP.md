# yvideo 工作区地图

**通用的视频与内容生产工作区**，装多个独立项目，不是单一产品。
根 `AGENTS.md` 是 DSH 自动加载的入口（每次会话都会读）；本文件是它的展开版：结构、项目索引、
跨项目约定、以及明写出来的结构债。

指令是**逐层叠加**的：根 `AGENTS.md` → 进入某个项目目录后，该项目自己的 `AGENTS.md` 追加生效。
所以"只属于某个项目的规则"应该写在那里，不要写在这里。

---

## 1. 结构

| 路径 | 是什么 | 入库 |
|---|---|---|
| `projects/<项目>/` | 每个项目一目录，**自治**；规则在各自的 `AGENTS.md` | 源与文档入库，媒体排除 |
| `doc/` | 跨项目知识：配音规范、本机 TTS 事实、坑与债 | ✅ |
| `tools/` | 脚本。**当前是「拆开 DSH」流水线**的工具（见结构债） | ✅ |
| `templates/` | 脚手架。**当前是「拆开 DSH」**的单集模板 | ✅ |
| `voice/` | 音色参考样本 | 仅 `.md`；`*.wav` 排除 |
| `out/` | 成片之外的产出（插画、封面、评测） | 小文件入库，媒体排除 |
| `learn/` | 第三方克隆，**只读**，各有自己的 `.git` | ❌ |
| `.agents/` | 共享技能安装，等价 `node_modules` | ❌ |

`.gitignore` 的口径是**按扩展名排除媒体**（`*.wav` / `*.mp4` …）+ 排除缓存与第三方克隆，
不按目录排除。所以"某个项目要不要入库"看它的文件类型，不看它在哪。

## 2. 项目

| 项目 | 状态 | 规则入口 | 产出 |
|---|---|---|---|
| 「拆开 DSH」系列 | 活跃（EP01–EP07 已发布，第二季排队） | `projects/dsh-anatomy/AGENTS.md` | `renders/`、`publish/epNN/`、`episodes/` |
| ydesk 讲解片 | 冻结，不再维护 | `projects/dsh-ydesk-explainer/AGENTS.md` | 同左，自带旧 `tools/` |
| 插画 / 封面 / 评测 | 零散 | `out/`（无流水线） | `out/whale-girl/`、`out/whale-skill-evals/` |

新项目：建目录 + 写 `AGENTS.md` + 说明源/生成/交付三层。跨项目入口（根 Makefile、`templates/`）
按需扩展，不要为了一个新项目去改别的项目。

## 3. 跨项目约定

1. ❌ 提交媒体（`*.wav` / `*.mp4` …）—— 体积大、可从源头重建
2. ❌ 改 `learn/` 里的任何东西 —— 第三方克隆
3. ❌ 提交密钥 / `.env`
4. ❌ 手改生成物 —— **默认如此**；每个项目的"源 / 生成 / 交付"分层由它自己的 `AGENTS.md` 定义。
   生成物该在 `generated/` 下（`tools/paths.py` 是唯一布局定义，G7 检查根上有没有旧残留），`index.html` 与 `compositions/captions.html` 例外——HyperFrames 契约要求它们在原位
5. ✅ 发布走对应平台的 skill（B站 / 抖音 / 小红书），回执留在项目目录（如 `publish/epNN/result.json`）。
   **回执是权威**：README「已交付」表由 `tools/delivery_table.py` 对账（`make readonly` 里跑），
   机器只指出缺口与不一致，不代笔——标题和括号注释是人的判断
6. ✅ **交付前跑 `make review`** —— 验收包落在 `renders/epNN-review/`（不进 git，随时可重建），
   入口 `REVIEW.md`：画面 / 时长账 / 字幕语速 / 波形 / 复听清单。它不进 `make verify`
   （改稿循环会被 40s 的重建逼到绕过），只接在 `make verify-all` 这条交付路径上；
   `make review-check` 判定它是否还描述着当前这一版。

7. ✅ **文档与代码冲突时以代码为准**（2026-11-28）。不是"看哪个新"，而是固定方向：
   文档是派生品，代码是事实。文档里抄了代码常量的地方（目前是 TTS 端点）由
   `tools/doc_facts.py` 对账（`make check-docs`，也在 `make verify-all` 里）；
   其余文字判断仍靠人，机器只盯"抄写走样"这一类。

8. ✅ **纠正必须落成检查，落不成的要写明为什么**。入口是 `doc/corrections.md` 的
   「固化形态」列；`make check-ledger` 盯这条链路本身（不许空、不许 `待办`、
   点名的脚本必须存在）。它判不了"漏记"，那半边只能靠收尾时人扫一遍。

9. ✅ **闸门要有回归**（`tools/selftest.py`，`make selftest`，进 `verify-all`）：
   夹具现场生成（两帧最小工程），每个用例注入一处故障，断言它必须红、且红的话说得对。
   被削弱的闸门不会自己报警——只会一路绿到交付，所以每加一条判据就要加一组用例。

## 4. 结构债（明写，别装作没有）

- **`tools/` 与 `templates/` 的位置是债**：内容是「拆开 DSH」一条流水线的，却放在工作区根，
  承担了"跨项目"的位置。第二条流水线出现时二选一：
  a) 移到 `pipelines/dsh/`（或项目内），根只留真正通用的东西；
  b) 保持现状，但承认"工作区根的 Makefile 只服务这条流水线"。
  **现在选 b**，并在根 `AGENTS.md` 里标注了"目前"。
- **`doc/` 里混了两种东西**：`配音指导.md`、`本机TTS-Qwen3.md` 是可复用的通用知识；
  `START-EPISODE.md` 只适用于「拆开 DSH」。
- **模板更新不回灌已建工程**：`make new-episode` 只在创建时复制。

## 5. 磁盘账（`make gc`）

整个工作区约 1.1G，**真正需要人保住的东西不到 300K**（脚本、文案、分镜、发布物）。
其余都是可重建物——但「可重建」不等于「该删」：

| 类 | 现在多大 | 删了怎么长回来 |
|---|---|---|
| safe | ~10M | 跑一次就回来（`__pycache__`、check 报告、波形缓存） |
| cache | ~130M | 重算：`.takes/` 要逐句 TTS；**并且失去「重跑音频逐字节一致」的验证前提** |
| derived | ~4M | `make review` 40s |
| expensive | ~680M | 重渲（5–15 分钟）、重配旁白、重新 clone（`learn/`） |
| keep | ~200M | 不删：被 STORYBOARD 引用的快照、工具编辑历史、音色参考、插画产出、技能安装 |

`make gc` 默认只报告。它存在的意义不是"腾空间"，是让"你正在背多少东西"可见——
所以每一条规则都必须写清重建代价，否则那只是又一个 rm 脚本。
