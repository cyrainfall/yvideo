# 配音指导（v2.1）—— 工作区通用声音层规范

> 适用：本工作区**任何片子**的声音层 —— 口播/旁白、音色选型、混音、字幕与时间戳。
> 本文件**不绑定具体片子**：片长、术语、上屏数字、禁语由各项目自己的 `SPEC.md` / `FACTS.md` 决定；这里只管「怎么做」与「怎么验收」。
> 方法论来源：[《AI 配音怎么做》整理笔记](./AI配音怎么做-视频整理.md)。
> 状态：`v2.1 · 2026-11-16`。默认走 A 路（本机/内网 TTS），默认音色「短视频走心男青年解说」。与某个项目的 SPEC 冲突时，**声音层以本文件为准**。

---

## 0. 一句话

**配音是时间轴，不是配乐。** 先有配音 → 拿到每句的起止时间 → 画面卡在句子边界 → 逐帧渲染。

- 「拿到时间」= **按句生成时累加**：一句一条 take（一次请求一句），按顺序拼轨，每句 `start` = 前面所有句长之和（含句间留白），`end` = `start` + 本句时长。**不需要字级时间戳，不需要 ASR 对齐。**
- 「卡在句子上」= 分镜的 `data-start` 直接引用句子时间，不写「大概 3.5 秒」。
- 只有需要**逐字卡拉OK高亮**或反向判词（G5）时，才用 `hyperframes transcribe` 取 word-level（§8.2）——不是交付的必经步骤。

## 1. 先决定：这片要不要人声

不要默认「每个视频都要配音」。按产物类型判断：

| 产物 | 典型时长 | 默认人声 | 理由 |
|---|---|---|---|
| 正片 / 长解说 | 3–10 min | **要** | 信息是因果链，字幕承载不了 |
| Teaser / 预告 | 10–90 s | **不要** | 信息流静音自动播放；开声音也不能吵 |
| 循环 GIF / hero 图 | ≤ 10 s | **不要**，静音 | 唯一能自动播放的资产 |
| 竖版切片 | 15–60 s | 默认不要 | 节奏快，口播会挤掉信息密度 |

**硬规则**：交付要求里写「必须有音轨」，指的是 BGM 必须存在，**不等于必须有人声**。这两件事是两个决定，不要混。

---

## 2. 唯一原则：配音是时钟

| 参数 | 取值 | 对配音的含义 |
|---|---|---|
| 帧率 | 按项目（多为 30 fps） | 1 帧 = 33.3 ms；音画偏移容忍 **≤ 1 帧** |
| 总长 | 由项目定 | 字数预算 = 总长 × 有效语速（§4.1） |
| 渲染方式 | 逐帧确定性（HyperFrames `render(t)`） | **禁止实时录屏**；声音回贴后天然对齐 |
| 时钟粒度 | 句 → 字 | 切点跟句子时间戳走，不跟「感觉」走 |

三条落地推论：

1. **先配音、后画分镜。** 「先把画面做完再配旁白」等于回去重剪一遍。
2. **一次一句、一条音频。** 按句切段（`voice/takes/NN.wav`），改一句只重配一句。
3. **时间戳是交付物。** `transcript.json`、`timing.json`、`out/*.srt` 与成片同级保留。
   本工作区**不是 git 仓库**：版本靠 `BUILD-LOG.md` 与文件命名，别在这里写 `git` 命令。

## 3. 音色选型

### 3.1 候选池

| 路径 | 代表音色 | 命令 / 接口 | 词级时间戳 | 代价 |
|---|---|---|---|---|
| **A（默认）本机 / 内网 TTS 服务** | **「短视频走心男青年解说」**（`d38028e2`）；自建服务，可克隆 / 可设计 | `POST /v1/audio/speech` | ✗ 另跑 ASR | 免费、可控、可克隆；占显存 |
| B 本地 Kokoro-82M | 见下方注 | `npx hyperframes@<pin> tts` | ✗ 需另跑 transcribe | 免费离线；韵律平 |
| C macOS `say` | 系统中文音（如 Tingting） | `say -v <voice>` | ✗ | 干声薄、齿音重，必须后处理 |
| D 平台 API | MiniMax / 豆包 / 千问 / ElevenLabs … | 各家 SDK 或 HTTP | 部分返回 | 音色最像人；有成本；key 要管 |
| E ASR | Whisper / Qwen3-ASR / Parakeet | — | ✓ | 只用来取时间，不配音 |

**默认路线与默认音色**：没有特别理由时走 **A 路**（本机 / 内网 TTS 服务），默认音色 **「短视频走心男青年解说」**（`voice_id: d38028e2`；服务地址与 key 走 `TTS_URL` / `TTS_KEY`）。理由：可克隆、可控、完全离线、按句合成快，已在本工作区的长片上跑通过。三条约束：

- 默认音色是**克隆音色**，参考音频必须自有授权 —— §3.3 里「禁止克隆」指的是**未经授权**拿别人的声音；
- **跨片沿用同一个音色**：观众认的是声音，不是每片换一个新音色。确实要换，按 §10 走全套验收；
- **A 路成立的前提是那台服务在线**（自建 / 内网机器，不是公网托管）。开工先探活，别等配到一半才发现连不上：
  `curl -fsS "$TTS_URL/health"`，或直接合成一句 1 秒的试听。
  服务不在时**按 §3.3 降级到 D 路平台 API**，并把降级原因写进 `voice.json` 与项目的 `BUILD-LOG.md`；
  不要因为默认路挂了就临时换音色 —— 音色一旦定下就是交付契约。

注：

- **Kokoro 的中文音色只有一个**（`hyperframes tts --list` 实测，0.8.x / 0.9.x 相同）。要换声音（含女声）走 A（克隆 / 设计）或 D（平台 API）。模型缓存在 `~/.cache/hyperframes/tts/`，离线可用。
- **A 路两个实测特性**，换服务也要先验：① 每段输出首尾各带 **~50 ms 静音**，对齐前要裁，否则起音晚半拍；② `speed` **不是纯重采样** —— 1.19× 时 F0 从 124 Hz 抬到 133 Hz（约 +1.2 半音）。所以全片用**一个基准语速**（如 1.08），只对装不进时间槽的句子做 ≤1.20× 的微调；相邻句 1.0 / 1.18 跳变人耳能听出来。

### 3.2 用测量代替形容词

同一段文本、同一切分，各路各合成一遍再比。下表是 Kokoro 与 `say` 的基准：

| 指标 | 怎么测 | 读什么 |
|---|---|---|
| 整体响度 / 真峰值 | `ffmpeg -af ebur128=peak=true -f null -` | 是否够 -14 LUFS（§7.2） |
| LRA | 同上 | **< 6 说明动态被压平**，长片听下来是「一条直线」 |
| 齿音（4–8 kHz） | 频谱或盲听对齐 | `say` 一类干声必刺，需 deesser |
| 韵律 / 停顿数 | 人耳 + 数停顿 | 停顿少 = 念稿感；同一引擎两次合成停顿数也会差 |
| 错字 / 漏字 | 反向 ASR + 逐字比对（§10 G5） | 自回归模型会偶发漏词，字面听不出来 |

实测基准（同一段中文、48 kHz mono 160k，可直接当量级参考）：

| 路 | 整体响度 | 真峰值 | LRA |
|---|---|---|---|
| Kokoro 原始 | -17.7 LUFS | -1.91 dBTP | 2.30 |
| `say` 干声 | -18.6 LUFS | -3.37 dBTP | 1.00 |
| `say` 后处理 | -16.5 LUFS | -1.93 dBTP | 0.80 |

三个可直接用的判断：

1. **三条都低于发布标准 -14 LUFS**，直接贴进片子会偏小，观众要拧音量；
2. **后处理把 LRA 从 1.00 压到 0.80**，说明是处理链把动态压平了 —— 「机械配音」的听感多半来自这里，不是音色；
3. 对照必须**同一段文本**，拿不同文本的样本比没有意义。

### 3.3 决策规则

```
默认（无特别理由）          → A 路本机/内网 TTS，音色「短视频走心男青年解说」，写进 voice/voice.json
要「作者本人的声音」        → 自己录（手机 + 安静房间 + 一次一句）
要「稳定可复现、换机可用」  → D 路平台 API，锁一个音色
只要「能听、免费、离线」    → B 路 Kokoro，接受韵律平
```

**禁用**：

- 克隆他人音色而**未取得授权**（涉及人格权与素材版权；自有参考音频的克隆见 §3.1 默认音色）；
- 全网同款的机械 TTS 音色（观众记不住）；
- 用「好听一点」「温柔一点」这类形容词驱动选型 —— 选型必须落到 §3.2 的指标。

## 4. 口播稿规范

口播稿是**独立交付物**（`voice/script.md`），不是从屏幕文案剪贴。屏幕文字给人「看」，口播稿给人「听」，两者句长、信息密度、术语密度都不同。

### 4.1 字数预算

有声语速按 **4.2–4.8 字/秒**（中文口播舒适区），再留 20% 给停顿换气 → **有效语速 3.2–4.0 字/秒**。

```
预算字数 = 时长（秒） × 3.2 … 4.0
```

| 时长 | 口播字数预算 |
|---|---|
| 30 s | 96–120 |
| 60 s | 192–240 |
| 90 s | 288–360 |
| 3 min | 576–720 |
| 7 min | 1344–1680 |

按段落（beat / 分镜段）切预算，每段单独核。**超预算就是超时长**：先数字数再配音，不要配完才发现多了一分钟。

### 4.2 句子规范

| 规则 | 值 | 为什么 |
|---|---|---|
| 单句长度 | ≤ 25 字 | 一句一镜，切点好对；长句 TTS 会自己乱断 |
| 一段一意 | 每段只推进一件事 | 与「症状→假设→实验→修复→数据」同构 |
| 数字密度 | 每句 ≤ 1 个数字 | 连续数字听不清，字幕也不好读 |
| 被动 / 多层从句 | 避免 | 口播的句子要能一口气念完 |
| 句间停顿 | 显式声明 150–300 ms | 写进 `pause.json`，不靠标点猜 |

### 4.3 术语读法表

每个片子建一张 `voice/读法规则.md`，配音前先按它改稿。表按下面几条规则生成，不要现场拍脑袋：

| 类型 | 规则 | 例 |
|---|---|---|
| 英文缩写 | 3 字母及以上逐字母读；有公认读法的连读，且**全片统一** | HTTP → 「H-T-T-P」；GPU → 「G-P-U」；JSON → 「杰森」 |
| 数字 + 单位 | 写成中文念法，稿子里不留阿拉伯数字 | 2048 B → 「二千零四十八字节」 |
| 单位进制 | MB=10⁶ 与 MiB=2²⁰ 分清，全片一种口径 | 1.3 MB/s → 「每秒一点三兆」 |
| 版本号 | 逐段读 | v0.1.0 → 「v 零点一点零」 |
| 命令行参数 | 口语化，连字符不念 | `-r 180` → 「把 r 设成一百八」 |
| 文件名 / 扩展名 | 「名字 + 点 + 扩展名」 | `config.yaml` → 「config 点 yaml」 |
| 多音字 | **换词，不靠标音** | 铺满 → 布满；重传 → 重新发送 |

### 4.4 数字与说法纪律

- 口播里出现的**每个数字都必须能在该片自己的数字清单**（`FACTS.md` 一类）查到，且与画面同源；
- 禁语清单是**项目级资产**：口播和画面受同一套约束，不能只禁画面不禁嘴；
- 区间永远读 min–max（「一点二四到一点三九兆」），不读单值；
- 倍数必须给基准（「2.7 倍，基准是 X ÷ Y」），不给裸倍数。

## 5. 每个片子的 `voice/` 目录约定

```
<project>/
├── voice/                    # 声音层，除 key 外全部保留
│   ├── script.md             # 口播稿（分 beat、带字数）
│   ├── 读法规则.md           # §4.3 的表 + 本片特例
│   ├── voice.json            # 音色决定：provider / voice_id / speed / 理由
│   ├── segments.json         # 句级清单（唯一真源）
│   ├── pause.json            # 句间停顿（ms）
│   ├── takes/                # 逐句音频 001.wav …；旧版进 takes/archive/
│   ├── transcript.json       # （可选）word-level 平铺数组；只在逐字高亮/判词时需要
│   ├── timing.json           # 句级索引：分镜抄它
│   └── mix.wav               # 混音母版（48k / 24bit）
└── out/
    ├── <片名>-<时长>.mp4
    ├── <片名>-<时长>.zh.srt
    └── <片名>-<时长>.en.srt
```

`segments.json` 是唯一真源：**改文案只改这里**，重跑合成只补缺的文件（已存在则跳过，`--force` 才覆盖）。

```json
{
  "voice": "d38028e2",
  "speed": 1.0,
  "segments": [
    { "id": "001", "beat": 1, "text": "先看这条链路。首包发出去，没有回音。", "chars": 21, "pause_after_ms": 200 }
  ]
}
```

**key 管理**：`voice/.env` 或环境变量。不许贴进对话框，不许写进 `voice.json` / `segments.json` / `BUILD-LOG.md`。

## 6. 生成

> 命令一律带版本号（`npx hyperframes@<pin> …`，pin 以项目 `package.json` 为准），避免 `npx` 漂移。

### 6.1 本机 / 内网 TTS 服务（A，默认）

自建服务（OmniVoice 一类）通常长这样：OpenAI 兼容的 `/v1/audio/speech`，`stream_format: "audio"` 时直接把 wav 流回来 —— **落盘即可，不要让中间层做 base64 回传**。

```bash
curl -s -X POST "$TTS_URL/v1/audio/speech" \
  -H "Authorization: Bearer $TTS_KEY" -H 'Content-Type: application/json' \
  -d '{"model":"<engine>","input":"…","voice":"d38028e2","language":"zh",
       "response_format":"wav","stream_format":"audio"}' \
  -o voice/takes/001.wav
```

- 默认音色 **「短视频走心男青年解说」= `d38028e2`**；换片不换音色（§3.1）；
- 输出多为 **24 kHz 单声道 s16**，进混音前统一重采样到 48 kHz；
- 每段首尾常带 **~50 ms 静音**，对齐前裁掉；`speed` 不是纯变速（见 §3.1 注）；
- 同一句合成两次**不是逐字节相同的**：停顿位置、偶发漏字都会变。要批量配，就合多版用 §10 G5 判词，取零缺陷那版；
- **不要**在同一台机器上同时用它的 `/v1/audio/transcriptions`：ASR 抢显存会把 TTS 队列一起卡死。ASR 走别的路径（§8）。

### 6.2 本地 Kokoro（B）

```bash
# 单句
npx --yes hyperframes@<pin> tts "先看这条链路。首包发出去，没有回音。" \
  -v <zh_voice> -s 1.0 -l zh -o voice/takes/001.wav

# 看有哪些音色
npx --yes hyperframes@<pin> tts --list
```

- 输出 wav 直接进混音，不转 mp3（mp3 只用于试听样本）；
- 韵律平是已知缺陷，靠 §4.2 的短句 + 显式停顿补救，**不靠调 speed**。

### 6.3 macOS `say`（C）

```bash
say -v Tingting -r 180 -o voice/takes/001.aiff \
  "先看这条链路。首包发出去，没有回音。"
```

- `-r` 是每分钟词数（不是字数），中文按 170–190 试；
- 输出 aiff，**先转 wav 再进混音**；干声齿音重、峰值只有约 -3.4 dBTP；
- 优点：零依赖、随时可重录；缺点：LRA 已经很平，再 loudnorm 会更「播报腔」。

### 6.4 平台 API（D）

按各家 HTTP 契约实现一个 `tts_synthesize <text> <out_path> [voice]` 即可，关键是**锁音色 + 记成本**。

```bash
# ElevenLabs 例
curl -s -X POST "https://api.elevenlabs.io/v1/text-to-speech/<voice_id>" \
  -H "xi-api-key: $ELEVENLABS_API_KEY" -H "Content-Type: application/json" \
  -d '{"text":"…","model_id":"eleven_multilingual_v2"}' -o take.mp3
```

**选型纪律**：音色定下来就写进 `voice.json` 并注明理由；换音色等于重配全片，要走一次 §10 的全套验收。

### 6.5 逐句合成的工程约束

| 约束 | 做法 |
|---|---|
| 可增量 | 文件名 = segment id；已存在则跳过 |
| 可回滚 | `takes/` 保留原件，旧版进 `takes/archive/`；无 git，按文件名版本号 + `BUILD-LOG.md` 追溯 |
| 可对齐 | 每句首尾留 **40 ms 静音**，混音时按句首对齐 |
| 可校验 | 合成后立刻对每句跑一次「反向识别 + 与原文逐字比对」（§10 G5） |

## 7. 后处理与混音规格

### 7.1 单句后处理链（A/C/D 必做，B 可选）

```bash
ffmpeg -y -i voice/takes/001.wav \
  -af "highpass=f=90,afftdn=nf=-25,deesser=i=0.4,acompressor=threshold=-18dB:ratio=3:attack=5:release=120,loudnorm=I=-16:TP=-1.5:LRA=9" \
  -ar 48000 -ac 1 -c:a pcm_s24le voice/takes/001.post.wav
```

| 环节 | 作用 | 对谁必须 |
|---|---|---|
| `highpass=f=90` | 去低频隆隆 / 桌面震动 | 都要 |
| `afftdn=nf=-25` | 轻度降噪（房间底噪） | 自录、`say` |
| `deesser=i=0.4` | 去齿音（「嘶」声） | `say` 类干声必须 |
| `acompressor=…` | 压掉句内起伏，保住句间呼吸 | `say`、Kokoro |
| `loudnorm=I=-16` | 单句统一到母版电平 | 都要 |

- 母版统一 **48 kHz / 单声道 / 24 bit**（与工作区其它音频资产一致，少一次重采样）；
- 单句先到 **-16 LUFS**，混音后再整体到发布标准，避免每句各自饱和；
- **不要**在单句上把 LRA 压到 6 以下：句内动态被压平后，长片听下来就是「一条直线」（见 §3.2）。

### 7.2 混音与发布响度

| 层 | 目标 | 依据 |
|---|---|---|
| 人声 | 整体 **-14 LUFS**，TP ≤ -1.5 dBTP | 社交平台发布标准 |
| BGM | 人声下约 **-31 LUFS**，不掩蔽语音 | 音乐只做底 |
| SFX | 峰值不超人声 -8 dB | 语义音效不能跳出来 |
| 交付 | 48k / 24bit wav 母版 + mp4 内嵌 AAC 192k | 与画面编码同批导 |

两遍 `loudnorm`（先测后压，别用一遍）：

```bash
# 1) 测
ffmpeg -hide_banner -i voice/mix.wav \
  -af loudnorm=I=-14:TP=-1.5:LRA=11:print_format=json -f null -

# 2) 用测得的 measured_* 回填（linear=true 只做增益，不改频谱）
ffmpeg -y -i voice/mix.wav \
  -af "loudnorm=I=-14:TP=-1.5:LRA=11:measured_I=<input_i>:measured_TP=<input_tp>:measured_LRA=<input_lra>:measured_thresh=<input_thresh>:offset=<target_offset>:linear=true:print_format=summary" \
  -ar 48000 -c:a pcm_s24le voice/mix.norm.wav
```

**BGM 闪避**：优先在 composition 里声明（可随时改，见 §9.3）；只有导出独立文件时才烘焙：

```bash
ffmpeg -i bgm.mp3 -i voice/mix.wav \
  -filter_complex "[0][1]sidechaincompress=threshold=0.03:ratio=8:attack=200:release=400[ducked]" \
  -map "[ducked]" bgm.ducked.wav
```

> 用 `alimiter` 时必须 `level=false`，否则限幅等于没做（峰值会被拉回 0 dBFS）。

## 8. 拿时间：句子级（默认）

**默认按句生成、按句取时间。** 一次合成一句，按顺序拼轨——句边界就是时间边界，拼接时把每句时长累加即可，既不需要 ASR 强制对齐，也就没有对齐误差。结果写进 `voice/timing.json` 的 `segments`，composition 的 `data-start` 直接抄。

下面 8.1/8.2 的 word-level 路径只在两种场合用：需要**逐字**高亮（卡拉OK字幕），或做反向判词（G5）。它属于可选项，不是每片必跑。

### 8.1 平台已经返回，就直接用

平台返回词级时间就**直接用**，不要再跑一遍 ASR（省一次误差）。写进 `voice/timing.json`。

### 8.2 兜底：`hyperframes transcribe`

```bash
# 中文口播：模型和语言都必须显式写（默认 small.en 会把中文翻成英文）
npx --yes hyperframes@<pin> transcribe voice/mix.wav \
  -d . --engine whisper --model large-v3 --language zh \
  --to=srt -o out/<片名>-<时长>.zh.srt
```

| 参数 | 说明 |
|---|---|
| `-d <dir>` | 项目目录；转写结果固定写成 `<dir>/transcript.json`（word-level 平铺数组），再 `mv` 进 `voice/` |
| `--to` / `-o` | 只作用于字幕 sidecar，不改变上面的 transcript |
| `--engine` | `auto` 会优先 Parakeet，但 **Parakeet 不覆盖中文**，中文显式写 `whisper` |
| `--model` | **必须显式**：`.en` 结尾会把中文**翻译成英文**（静默毁掉原文）。中文用 `medium` 或 `large-v3`（不带 `.en`） |
| `--language zh` | 同时过滤非中文片段，混英文术语时更稳 |
| `--preserve-cues` | 稿子已有逐句 cue（CJK 单句无空格）时用它，别让框架重新分组 |

模型体积与耗时（首次自动下载）：

| 模型 | 体积 | 7 分钟中文 |
|---|---|---|
| `small` | 466 MB | 快，但数字/术语容易错 |
| `medium` | 1.5 GB | 可用，改稿返工多 |
| `large-v3` | 3.1 GB | 最准，生产用 |

**成本提示**：批量改稿时只重转改过的句子（把改动句单独合成成一条临时 wav），别整片重跑。

### 8.3 两种时间文件的契约

**`voice/transcript.json`** —— CLI 产出的 word-level 平铺数组，composition 直接消费，**不要自己改格式**：

```json
[
  { "id": "w0", "text": "先", "start": 0.42, "end": 0.55 },
  { "id": "w1", "text": "看", "start": 0.55, "end": 0.72 },
  { "id": "w2", "text": "这条", "start": 0.72, "end": 1.10 }
]
```

**`voice/timing.json`** —— 句级索引，**默认由按句拼接直接累加得到**（不依赖 transcript.json）；也可以由 `segments.json` 的句边界去 transcript 里找首尾字推导。给写 `data-start` 用：

```json
{
  "source": "voice/mix.wav",
  "engine": "whisper-large-v3",
  "segments": [
    { "id": "001", "beat": 1, "start": 0.42, "end": 3.10,
      "frame_start": 13, "frame_end": 93, "text": "先看这条链路。" }
  ]
}
```

规则：

- 时间单位 **秒、浮点、2 位小数**；`frame = round(t × fps)`（30 fps 时 1 帧 = 33.3 ms）；
- `id` 与 `segments.json` 一一对应，对不上就是错（§10 G4）；
- 只写 `timing.json` 做校对，**别手改 `transcript.json`** —— 重跑 transcribe 会覆盖。

## 9. 接进 HyperFrames

### 9.1 硬性要求（违反就静音或 lint 报错）

| 要求 | 说明 |
|---|---|
| 音频放在**宿主 `index.html` 根节点** | 子组合的 timeline 驱动不了宿主元素；音频要跨场景存活 |
| 每个 `<audio>` **必须有 `id`** | 没有 id 的音频不进 mixer，渲染出来是静音；lint 直接报 `media_missing_id` |
| 用 `data-start` / `data-media-start` 定位 | `data-media-start` 是**源文件内**偏移，用来跳过前几秒而不用裁文件 |
| 不给 `.clip` 元素做 opacity/visibility 动画 | 生命周期由框架管，动画会打架；要动就包一层 wrapper |

### 9.2 两种接法，按片长选

**A. 整条旁白（推荐给长片）**

```html
<audio id="vo" data-start="0" data-track-index="2" src="./assets/audio/voice-mix.wav"></audio>
<audio id="bgm" data-start="0" data-track-index="1" src="./assets/audio/score.m4a"></audio>
```

> **跨目录说明**：`voice/` 在项目根，composition 常在自己的子目录里。二选一：
> ① 渲染前 `cp voice/mix.wav <comp>/assets/audio/voice-mix.wav`（推荐，最稳）；
> ② 在 composition 目录建软链。
> **不要**让 composition 直接写 `../voice/...` —— asset 解析策略一变就静默失效。

**B. 按句切片（需要单句重配/重排时）**

```html
<audio id="vo-001" data-start="0.42" data-track-index="2" src="./voice/takes/001.post.wav"></audio>
<audio id="vo-002" data-start="3.10" data-track-index="2" src="./voice/takes/002.post.wav"></audio>
```

同一条 track 上**重叠**会触发 `duplicate_audio_track` 警告 —— 切片要首尾相接，不要叠。

### 9.3 BGM 闪避写在 composition 里

```html
<audio id="bgm" data-start="0" data-track-index="1" src="./assets/audio/score.m4a"
  data-automation='{"version":1,"lanes":[{"target":"volume","points":[
    {"t":0,"v":0.6},{"t":3.42,"v":0.6},{"t":3.57,"v":0.15},
    {"t":9.87,"v":0.15},{"t":10.27,"v":0.6}]}]}'></audio>
```

时间点从 `timing.json` 的句子边界取，不要手写「大概 3.5 秒」。

## 10. 验收门（配音版）

沿用 `check.sh` 的风格：**exit 非 0 就是没过**，警告不许静默通过。

| 门 | 检查 | 命令 / 方法 | 通过标准 |
|---|---|---|---|
| **G1 时长** | 口播总长 + 停顿 ≤ 预算 | 取 `timing.json` 末句 `end` + `pause.json` | 成片时长 ± 3 s |
| **G2 语速** | 实际字/秒 | 字数 ÷ 有声时长 | 4.2–4.8 字/秒 |
| **G3 响度** | 整体 LUFS / TP | 两遍 loudnorm | -14 LUFS ±0.5，TP ≤ -1.5 |
| **G4 段落一致** | `segments.json` 的 id 集合 = `timing.json` 的 id 集合 | `jq` 对比 | 差集为空 |
| **G5 判词** | 每条 take 反向识别后与原文逐字比对 | `hyperframes transcribe` + diff | 差异 0 字；插入/删除、5 字以上塌缩一律算缺陷，多音字按 §4.3 换词解决 |
| **G6 音画对齐** | 每个「卡词」镜头的 `data-start` 与句首偏差 | `round(t × fps)` 比对 | ≤ 1 帧 |
| **G7 静音可懂** | 关声音看片 | 人工 | 能看懂主线 |
| **G8 有声不吵** | 开声音看片 | 人工 | BGM 不掩蔽人声；SFX 不跳出来 |
| **G9 数字合规** | 口播数字 ⊆ 项目数字清单 | 人工 + `grep` | 无表外数字、无禁语 |
| **G10 整片规格** | 容器 / 编码 / 帧数 / 有音轨 | 项目 `tools/check.sh <mp4> <w> <h> <fps> <min> <max> 1` | 末行 `OK` |

## 11. 常见故障

| 症状 | 根因 | 对策 |
|---|---|---|
| 渲染出来没声音 | `<audio>` 没 id，或放进了子组合 | 挪到宿主根节点 + 给 id（§9.1） |
| 音画差半拍 | 用了「感觉」的时间 | `data-start` 抄 `timing.json`，别手写秒数 |
| 数字/术语被念错 | 稿子里写了阿拉伯数字和缩写 | 按 §4.3 改成中文念法，建读法表 |
| 长片听下来「一条直线」 | 单句后处理把 LRA 压平了 | 句内压缩 ≤3:1，LRA ≥ 6（§7.1） |
| 手机上听不到 BGM 低频 | 能量写在 55 Hz 一类手机扬声器死角 | 低频层挪到 200–400 Hz |
| 每句开头一个怪音（像「让」/清嗓子） | 引擎自带的非文本起音，在首字之前 | 静音到首字前 10–15 ms；按包络找，ASR 听不出来 |
| 停顿里一声「嗒」/一口气 | 引擎往停顿里留咔哒或呼气 | 只静音不删样本（保时间戳），逐处处理 |
| 某句漏字 / 少一个词 | 长文本一次自回归生成会漏 | 合多版 + §10 G5 判词取零缺陷版；关键句拆短重配 |
| 改了母版后旧瑕疵又回来 | 后处理跑在**旧文件**上 | 让清洗步骤对「当前母版」每次都跑，不缓存 |
| 字幕把中文翻成了英文 | 用了 `.en` 结尾的 whisper 模型 | 显式 `--model large-v3 --language zh` |
| 对齐显示完美（delta 0）但切点在句子中间 | 对齐回退分支静默用了估计值 | 打印吸附方式（snap / estimate），出现 estimate 就报警 |

## 12. 与《AI 配音怎么做》的对照

| 笔记里的动作 | 本工作区怎么落 |
|---|---|
| 先有配音再有画面 | 先跑 `voice/`，再改 `compositions/*` 的 `data-start` |
| 强制对齐（三种做法） | 平台返回 → `timing.json`；兜底 `hyperframes transcribe`；再兜底本地 ASR |
| 让 AI 读懂稿子、把画面卡在词上 | 分镜 `data-start` 抄句首时间；分镜表写「卡在哪个字」 |
| 一帧一帧导出，不实时录 | HyperFrames 逐帧确定性渲染 |
| 四种配音方式选型 | §3.1 候选池 + §3.3 决策规则 |
| 用 API 而不是网页 | 走 CLI/HTTP，不手工点网页 |
| key 存文件、不贴对话框 | `voice/.env` 或环境变量，不进 `voice.json` / BUILD-LOG |
| 说风格让 Agent 挑音色 | 用 §3.2 的实测指标筛，人耳定稿 |
| 「好看一点」没用 → 写规格 | 声音同理：不写「温柔一点」，写「4.2–4.8 字/秒、LRA ≥ 6、齿音不刺」 |
| 剪映导出字幕要会员 | `hyperframes transcribe --to=srt` 免费出 SRT |
