## 0. 这期在解决什么问题

作者视频里的配音、字幕、画面全是 AI 做的，而且画面**总在说到那个词的时候刚好出来**。观众最常问的是三个问题：

1. 字幕为什么能和配音一个字都不差？
2. 画面为什么能卡在某个词上？
3. 导出之后为什么不会错位？

这期只讲**配音**（画面留到下一期），定位是「全网最细的 AI 配音教程」，因为配音一旦定下来，字幕、画面、导出全都是它的下游产物。

---

## 1. 原理：配音是整条视频的时钟

> 核心就一句话：**配音是整条视频的时钟。**

传统做法是「先剪画面，再配音，然后一点点去对」；作者的做法完全相反——**先有配音，再有画面**。稿子写好，先把整篇配音生成出来，这条配音里「第几秒在说什么」本身就是整条视频的时间表，字幕和画面全都跟着它走。

四步流程：

```
① 先有配音  →  ② 算出每个字的时间  →  ③ 让 AI 把画面卡在词上  →  ④ 一帧一帧导出来
```

### 1.1 第一步：先有配音，再有画面

- 稿子写好之后，**第一件事是整篇生成配音**，而不是先摆画面。
- 生成的配音天然带一条时间表：第几秒在说哪句话、哪个词。
- 这份时间表是后面所有工作的唯一基准（single source of truth）。

### 1.2 第二步：算出每个字是第几秒说的（强制对齐）

比喻很精准：**就像拿着歌词本听歌**。歌词你早就知道（稿子是你自己写的），你要做的只是听出每个字**从第几秒开始、到第几秒结束**。这一步专业上叫**强制对齐（forced alignment）**。

做法有三种，按优先级排列：

| 方式 | 做法 | 特点 |
| --- | --- | --- |
| ① 配音模型自带 | 生成配音时，平台自己返回每个字的时间戳 | 最省事，首选 |
| ② 专门的对齐模型 | 用 ASR / 对齐模型对音频重新识别，反推时间 | 通用，可控，可接进工作流 |
| ③ 剪映字幕识别 | 把配音拖进剪映，用「识别字幕」拿到时间 | 兜底方案，导出字幕文件要会员 |

三种方式后面实操都会带一遍。

### 1.3 第三步：让 AI 读懂你在讲什么，把画面卡在词上

有了每个字的时间，接下来交给大模型。它会**一句一句读稿子，判断这句话在讲什么**，然后决定画面：

| 稿子里在讲 | 画面就做成 |
| --- | --- |
| 数据 | 图表 |
| 步骤 | 流程图 |
| 引用别人的原话 | 截一张真实网页 + 荧光笔标注 |
| 提到某个产品 | 把它的 logo 放上来 |

然后每一个动画都被写成可执行的规格，句式是：

> **说到某个词的那一刻，某个东西出现。**

视频里用一段对照演示了「差不多对上」有多糟：同一句话，画面比配音**只差半秒**，观感立刻别扭。所以画面不能「大概对上」，要**精确到每一个词**。

### 1.4 第四步：为什么导出来不会错位

关键认知：**这些画面没有一帧是边播边录的**，全部是按时间一帧一帧算出来的。

- 一秒 60 帧；
- 第 600 帧就画「第 10 秒该有的样子」；
- 全部画完，再把配音放回去；
- 每一帧和声音天然对齐，**电脑卡一下也不会错位**。

这是整条流水线能稳定复现的根本原因：渲染是确定性的，不依赖实时性能。

## 2. 选型：市面上主流的四种配音方式

| # | 方式 | 优点 | 问题 | 作者的判断 |
| --- | --- | --- | --- | --- |
| 1 | **自己配音** | 效果肯定最好 | 门槛极高：没训练过就要反复重录、剪气口、降噪，光配音就能让人放弃；声音不出镜的话没必要 | 不建议一上来就自己配 |
| 2 | **机械配音**（机械感很重的传统 AI 音色） | 便宜、随手可得 | 没感情，容易做成营销号；全网都在用的声音，观众记不住你 | **最不推荐** |
| 3 | **克隆别人的音色** | 听起来像真人 | 网上很多人用，但没那么好用：克隆出来不自然，除非花大量时间训练，否则观众一听就知道是 AI | 做科普/动画没必要折腾 |
| 4 | **生成式语音大模型 + 平台自带音色** | ① 可以自己挑，找到符合频道风格的声音；② 方便省时间；③ 效果不算最好但绝对不差；④ 最贴近 AI 工作流 | 需要自己试听、自己挑 | **作者当前方案，推荐** |

> 边界说明：以上判断只针对「科普 / 动画类视频」。做短剧或别的类型，这条建议不适用。

**第 4 种的核心优势不是「最像人」，而是「能挑、够用、可编程」**——它能被 Agent 直接调用，才是关键。

## 3. 去哪里用、为什么用 API

### 3.1 模型从哪来

| 类别 | 选项 |
| --- | --- |
| 国产商用 API | 豆包、千问、MiniMax |
| 开源自部署 | 千问开源的 Qwen3-TTS、B 站开源的 IndexTTS |
| 作者在用 | ElevenLabs |

作者的通用建议：**自己上去挑一个合适的套餐，直接调 API**；不知道选哪个就去看语音模型的测试排行，但**一定要自己实际听一下**，觉得不错就用它。

### 3.2 为什么建议用 API，而不是网页生成

| 维度 | 网页生成 | 调 API |
| --- | --- | --- |
| 能否出片 | 可以，把音频交给字幕模型生成带时间的字幕一样能用 | 可以 |
| 控制粒度 | 粗 | 细：哪里停顿、带什么情绪、长句怎么断开，都能写进参数 |
| 一次成型 | 常要反复试 | 一次生成就是想要的样子 |
| 工作流 | 手工 | 模型直接调用，可搭成稳定的自动化流水线，效率大幅提升 |

> 作者的态度很明确：不嫌麻烦的话网页也能干活；但要想**稳定复用**，就直接上 API。

## 4. 实操：15 秒科普动画《为什么天空是蓝色的》

演示组合：**DeepSeek + DeepSeek Harness**（换成任何 Agent 都可以）。目标：让 Agent 从零做一条 15 秒科普小动画——**配音、字幕、画面全交给它**。

### 4.1 准备四份文件

先建一个文件夹，放四份说明文件。**技术细节全写在文件里，对话框里只说大白话**——这是整套方法能跑通的前提。

| 文件 | 写什么 | 作用 |
| --- | --- | --- |
| `稿子` | 这 15 秒要念的话 | 唯一的文本源（后续配音、字幕、画面都从它派生） |
| `读法规则` | 告诉它稿子怎么改，配音才不读错 | 多音字、数字、英文、断句的处理约定 |
| `配音设置` | 用哪个平台、key 放在哪、音色先不填 | 让 Agent 自己去平台找音色，而不是等人指定 |
| `画面要求` | 画面多大、什么配色、字幕怎么放、怎么导出 | 渲染规格 + 审美约束 |

### 4.2 第一步：拿 key

- 打开你用的配音平台，在后台**新建一个 API key**；
- **最好存进文件里，别直接贴进对话框**；
- 作者的现场插曲很能说明 Agent 行为：这次 key 文件忘了填，Agent 读完文件发现是空的，**没有接着乱跑，而是停下来问「key 怎么给我」**——确认后才把 key 写进文件。

> 可用性提示：把 key 放文件 + 让 Agent 主动确认，比把 key 塞进 prompt 更安全，也更容易复现。

### 4.3 第二步：说风格，让它自己挑音色

作者只说了**一句大白话**：

> 想要一个年轻女性的声音，温柔、吐字清楚、适合讲科普，帮我挑四个，每个用稿子第一句生成一段试听。

有意思的地方来了：**Agent 听不到声音，那它怎么挑？** 它自己设计了一套筛选流程：

1. 先在平台约 6 万个音色里，按「中文女声」筛出 **60 个**；
2. 再从里面挑 **10 个**真正生成一遍；
3. 测每个声音的**音高和语速**；
4. 把生成的声音**再识别回文字**，看吐字清不清楚；
5. 最后给出 **4 个候选**，每个都写明语速、音高和特点。

结果：Agent 推荐第二个，但作者在它多给的几个备选里，**挑中了一个自己更喜欢的**。

> 结论：**挑音色这件事 AI 能帮你把范围缩小，最后还是要你自己听。** 这是少数必须人来做的环节。

### 4.4 第三步：整篇配音

- 定下音色后，让它**先按读法规则改一遍稿子，再整篇生成配音**；
- 这次它只改了一处：把「铺满」换成「布满」——因为「铺」是多音字（pū / pù），有可能读成「布」的音；「布满」只有一个读音、意思一样；
- 生成完它还**自己把配音识别了一遍，跟稿子逐字比对**，**65 个字全部对上**。

这一步展示了「自检」的价值：配音的正确性不是靠人耳朵抽查，而是靠「反向识别 + 逐字 diff」这条可自动化的验收标准。

### 4.5 第四步：拿到每个字的时间

- 文件夹里除了配音，**多了一份时间表**：每个字从第几秒开始、到第几秒结束；
- 这是配音平台在生成配音时**一起返回**的，首选；
- **但不是每个平台都会给**。如果平台不返回时间，或者你是自己录的音、在网页上配的音，有两个办法：

| 办法 | 操作 | 注意 |
| --- | --- | --- |
| 剪映 | 把配音拖进去，用「识别字幕」拿到每一句的时间 | 想把字幕**导出成文件要开会员** |
| **Qwen3-ASR**（作者推荐） | 阿里千问开源（2026 年 1 月）的语音识别模型，只有 0.6B 参数，一张 4G 显存的显卡就能跑，GitHub 搜索即可找到 | 把地址丢给 AI，它会自己装好 |

作者推荐 Qwen3-ASR 的三条理由：

1. **模型可以直接调用**，不用手动去点；
2. 方便，准确率也高；
3. 后面还能把它**做成 MCP**，接进自己的工作流——作者现在就是这么用的。

### 4.6 第五步：按时间做画面

有了配音和时间，最后让 Agent 按画面要求把稿子做成动画，**画面和字幕都跟着声音走**。

第一版翻车了：画面很空，只有一个小点和几根细线；改了一次还是不行，整条就是一个太阳在发光，什么都没讲。

问题定位得很准：

> 我只跟它说「好看一点」——它不知道什么叫好看，只会往上加光效。

于是换办法：给它一份**美术分镜**，写清楚——

- 什么风格；
- 哪几种颜色；
- 每个镜头画什么；
- 画多大；
- 卡在哪个字上。

然后让它**推翻重做**。

> 通用结论：**想让 AI 做出好看的画面，光说「好看一点」没用，要把你想要的样子写成它能照着做的规格。**

### 4.7 第六步：导出成片

和原理里讲的一样：按时间一帧一帧画出来——

- 一秒 60 帧，15 秒，**一共 932 帧**；
- 画完再把配音放回去；
- 成片里画面确实跟着声音在变。

作者自评：再优化一下还能更好看，但这期是配音教学，画面先不纠结，后面单独出一期讲怎么用 DeepSeek 做好看的画面。

## 6. 总结：原理四步 + 实操三件事

### 原理（四步，背下来就够）

1. **先有配音**；
2. **算出每个字的时间**；
3. **让 AI 把画面卡在词上**；
4. **一帧一帧导出来**。

### 实操（三件事）

| # | 要点 |
| --- | --- |
| 1 | **把 key 和几份说明文件准备好**——技术细节写进文件，对话框只说大白话 |
| 2 | **时间优先用平台返回的**；没有就用剪映，或者千问的字幕模型（Qwen3-ASR） |
| 3 | **想要画面好看，就把审美写成它能照做的规格**——不是形容词，是分镜 |

### 00:33 原理：配音是整条视频的时钟

你可能好奇：我视频里的字幕和配音一个字都不差，画面也总是在说到那个词的时候刚好出来，这是怎么做到的？核心就一句话——**配音是整条视频的时钟**。

**第一步，先有配音，再有画面。** 很多人做视频习惯先剪画面再配音，然后一点一点去对；我正好反过来：稿子写好，先把整篇配音生成出来。这条配音里第几秒在说什么，就是整条视频的时间表，字幕画面全都跟着它走。

**第二步，算出每个字是第几秒说的。** 就像拿着歌词本听歌：歌词你早就知道了，因为稿子是你自己写的；你要做的只是听出每个字从第几秒开始、到第几秒结束。这一步专业上叫「强制对齐」。做法有三种：第一种，配音模型自己就会告诉你每个字的时间；第二种，用专门做对齐的模型来算；如果这两样都没有，还有第三种——把配音拖进剪映，用它的字幕识别一样能拿到时间。这三种怎么操作，后面实操我一个一个带你看。

**第三步，让 AI 读懂你在讲什么，把画面卡在词上。** 有了每个字的时间，接下来交给大模型：它会一句一句读你的稿子，判断这句话在讲什么——讲数据就做成图表，讲步骤就做成流程，引用别人的原话就截一张真实的网页、画上荧光笔，提到某个产品就把它的 logo 放上来。然后每一个动画都会被写成这样一句话：说到某个词的那一刻，某个东西出现。

我们直接看一个例子：我先写好稿子，再把它变成声音，然后算出每个字的时间，最后让画面跟着声音走。（此处画面与配音只差半秒）……只差半秒，是不是马上就别扭了？所以画面不能大概对上，要精确到每一个词。

**第四步，为什么导出来不会错位。** 这些画面没有一帧是边播边录的，全是按时间一帧一帧算出来的：一秒 60 帧，第 600 帧就画第 10 秒该有的样子，全部画完，再把配音放回去，每一帧和声音天然对齐，电脑卡一下也不会错位。

原理就这四步：先有配音、算出每个字的时间、让 AI 把画面卡在词上、最后一帧一帧导出来。

### 02:48 怎么选：四种配音方式

市面上主流的大概有四种。

**第一种，自己配音。** 效果肯定最好，优点也很多，但门槛真的太高了：没专门训练过的话，录音、重新录、剪气口、降噪，光是配音花的时间就可能让你直接放弃；而且如果你声音本来就不算好听、又不出镜，用 AI 配音完全没问题。所以我不建议一上来就自己配。

**第二种，机械配音**，就是那种机械感很重的 AI 音色——一股机械味道，没有什么感情。这种我最不推荐，做着做着很容易做成营销号；全网都在用的声音，观众是记不住你的。想认认真真做自媒体，别用这种。

**第三种，克隆别人的音色。** 网上很多人在用，但用过的都知道没那么好用：克隆出来的声音不太自然，除非花大量时间训练，不然观众一听就知道是 AI 在说。大多数人的声音本来也没专门训练过，我觉得没必要折腾。

当然我说的只针对像我这样做科普、做动画类的视频；如果你做短剧或者别的类型，就当我没说。

**第四种，也是我现在用的：用生成式的语音大模型，直接选平台上自带的音色。** 为什么推荐它？第一，可以自己挑，找到最符合你频道风格的声音；第二，方便省时间，不用花多少精力就能找到一个好听的配音；第三，效果我不敢说最好，但绝对不差；第四，它特别方便接近 AI 的工作流。

### 04:18 去哪里用、为什么用 API

去哪里用？你可以去市面上主流的模型厂商那里拿 API：国产比较有名的有豆包、千问、MiniMax；也可以用开源的模型，比如千问开源的 Qwen3-TTS，还有 B 站开源的 IndexTTS。我个人用的是 ElevenLabs。总之你自己上去挑一个觉得合适的套餐，然后直接调用它的 API 就行。如果你不知道用什么模型，可以去看一下相关的测试排行，哪个模型能力比较强、效果比较好；不过我建议你们自己都去实际听一下，觉得不错就用它。

这里说一下为什么我建议用 API。其实你不嫌麻烦的话，直接在他们的网页上生成也是可以的：把生成好的音频交给字幕模型，生成带时间的字幕文件一样能用。但用 API 的话，AI 可以帮你控制得更细——哪里停顿、带什么情绪、长句怎么断开，都能写进去，一次生成就是你想要的样子。而且如果你想搭一套自己稳定的工作流，我建议直接用 API，这样模型直接调用，你的工作效率可以大大提高。

### 05:18 上手实操：DeepSeek + Harness

最后上手实操。为了方便大家理解，这次演示我用的是 DeepSeek 搭配 DeepSeek Harness，你用其他任何 Agent 都是可以的。目标是让它从零开始，做一条 15 秒的科普小动画——「为什么天空是蓝色的」，配音、字幕、画面全部交给它。

**先准备一个文件夹，里面放四份文件：**

- **稿子**：就是这 15 秒要念的话；
- **读法规则**：告诉它稿子怎么改，配音才不读错；
- **配音设置**：写用哪个平台、key 放在哪，音色先不填，让它自己找；
- **画面要求**：写画面多大、什么配色、字幕怎么放、最后怎么导出。

技术细节全写在文件里，对话框里我只说大白话。

### 06:00 拿 key

第一步，拿 key。打开你用的配音平台，在后台新建一个 API key，最好存进文件里，别直接贴进对话框。

我这次 key 文件忘了填，它读完文件发现是空的，没有接着乱跑，停下来问我「key 怎么给我」，我就直接贴给了它，它帮我写进了文件。

### 06:16 说风格，让它自己挑音色

第二步，说风格，让它去找音色。我只说了一句：「想要一个年轻女性的声音，温柔、吐字清楚、适合讲科普，帮我挑四个，每个用稿子第一句生成一段试听。」

接下来就有意思了——它听不到声音，那怎么挑？它是这么做的：先在平台 6 万个音色里按「中文女声」筛出 60 个，再挑 10 个真的生成一遍，测每个声音的音高和语速，最后把生成的声音再识别回文字，看吐字清不清楚。最后给了我四个候选，每个都写了语速、音高和特点。

（四段试听依次播放）它推荐第二个，不过我反而在它多给的几个备选里，挑中了一个自己更喜欢的。所以挑音色这件事，AI 能帮你把范围缩小，最后还是要你自己听。

### 07:26 整篇配音

第三步，整篇配音。定下音色，让它先按读法规则改一遍稿子，再整篇生成配音。

它只改了一处：把「铺满」换成了「布满」。因为「铺」是多音字，有可能读错成「布」；而「布」只有一个读音、意思一样。生成完它还把配音自己识别了一遍，跟稿子逐字比对，65 个字全部对上。

### 08:05 拿到每个字的时间

第四步，拿到每个字的时间。这时候你会发现文件夹里除了配音，还多了一份时间表，每个字从第几秒开始、到第几秒结束都写在里面。这是配音平台在生成配音时一起返回的，有了它，每个字在第几秒就都知道了。

但不是每个平台都会给。如果你用的平台不返回时间，或者你是自己录的音、在网页上配的，有两个办法：

第一个，剪映：把配音拖进去，用它的「识别字幕」就能拿到每一句的时间。不过要注意，想把字幕导出成文件，要开会员。

第二个，也是我推荐的，**Qwen3-ASR**：这是阿里千问今年 1 月开源的语音识别模型，只有 0.6B 参数，一张 4G 显存的显卡就能用，在 GitHub 上搜 Qwen3-ASR 就能找到。把地址丢给 AI，它会自己装好。为什么推荐它？第一，模型可以直接调用，不用你手动去点；第二，方便，准确率也高；第三，后面还能把它做成 MCP，搭建你自己的工作流——我现在就是这么用的。

### 09:09 按时间做画面

第五步，按时间做画面。有了配音和时间，最后一步让它按画面要求把稿子做成动画，画面和字幕都跟着声音走。

第一版出来，说实话不好看：画面很空，就一个小点和几根细线。我让它改了一次还是不行，整条就是一个太阳在发光，什么都没讲。问题在哪？我只跟它说「好看一点」——它不知道什么叫好看，只会往上加光效。

所以我换了个办法：给它准备了一份**美术分镜**，什么风格、哪几种颜色、每个镜头画什么、画多大、卡在哪个字上，全部写清楚，然后让它推翻重新做。

想让 AI 做出好看的画面，光说「好看一点」没用，要把你想要的样子写成它能照着做的规格。

### 09:55 导出成片

最后导出成片。跟原理里讲的一样，按时间一帧一帧画出来：一秒 60 帧，15 秒，一共 932 帧；画完再把配音放回去。可以看到画面确实是跟着声音在变化的。

再优化一下还能做得更好看，不过这期是配音的教学，画面就先不纠结了。如果大家感兴趣，后面的视频我再教大家怎么用 DeepSeek 做出好看的画面。

### 10:37 总结

好，我们回到配音。从拿 key、挑音色、配音、拿时间到做画面，整个过程我基本只是在说话，具体的活都是 AI 干的。

最后总结一下：原理就四步——先有配音、算出每个字的时间、让 AI 把画面卡在词上、最后一帧一帧导出来。选择上，我推荐直接用平台自带的音色、用 API 来调用。实操上记住三件事：把 key 和几份说明文件准备好；时间优先用平台返回的，没有就用剪映或者千问的字幕模型；想要画面好看，就把审美写成它能照做的规格。

干货就讲到这里，最后聊几句我自己的经历。这套配音我其实摸索了很久。一开始我也试过自己配、拿 iPhone 录音，结果就像前面说的，剪辑、处理、剪气口花了半天，效果还大打折扣。后来我换了 MiniMax，又换了 Gemini、Fish Audio，效果都没达到我的预期，坑是真的踩了不少，最后才换成了你现在听到的这个声音。

## 附录 D：可直接复用的文件骨架

> 以下骨架是根据视频里「四份文件」的分工补全的，方便直接开一个项目文件夹就开工。

```
project/
├── 稿子.md          # 15 秒要念的话，唯一文本源
├── 读法规则.md      # 多音字 / 数字 / 英文 / 断句约定
├── 配音设置.md      # 平台、模型、key 路径、音色（留空让 Agent 自选）
├── 画面要求.md      # 画幅、配色、字幕位置、导出规格
└── api_key.txt      # 不入库、不进对话框
```

`读法规则.md` 建议至少覆盖：

- 多音字一律替换成单读音同义词（如「铺满」→「布满」）；
- 数字、单位、英文缩写的读法（如 450nm 读「四百五十纳米」）；
- 长句在哪里断，哪里要停顿；
- 情绪基调（本片中：温柔、吐字清楚、科普感）；
- 交付验收标准：生成后必须「反向识别 + 与稿子逐字比对」，字数必须一致。

`画面要求.md` 建议写成规格而不是形容词：

| 字段 | 示例 |
| --- | --- |
| 画幅 / 帧率 | 1920×1080，60fps |
| 时长 | 15 秒（932 帧，含尾帧） |
| 风格 | 扁平 + 微质感，不用光效堆砌 |
| 配色 | 主色 / 辅色各写死色值 |
| 字幕 | 位置、字号、安全区、逐词高亮规则 |
| 镜头表 | 每个镜头：画什么、画多大、卡在哪个字 |
| 导出 | 帧序列 + 音频回贴，禁止实时录屏 |
