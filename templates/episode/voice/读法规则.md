# EP07 读法规则（配音前按此改稿）

> 依据 `doc/配音指导.md` §4.3。本机 Qwen3-TTS Base 在中文句子里遇到英文标识符时的实测错误，以及本片采用的写法。
> 测试方法：同一音色合成短句 → whisper（英文定向）回听，比对听感与写法。

## 这份表和闸门的关系

**机器读的是 `voice/lexicon.json`，不是这份 md。**`tools/en_check.py` 只认那张表。

新增一条经验必须三处同步，缺一处闸门就形同虚设（这正是以前"靠记性"的老问题）：

1. 本表加一行（人读的来龙去脉、实测证据）
2. `voice/lexicon.json` 加一行（闸门的硬规则）：`"屏上写法": "口播写法"`
3. `make readonly` 跑 selftest 回归，确认新规则拦得住、旧内容不误报

实测读得清、要放行的写法进 lexicon 的 `spoken_ok`，不要写进 `spoken`（会被拦）。

## 缩写 / 标识符

| 屏上写法 | 口播写法 | 原因（实测） |
|---|---|---|
| `ctx` | `C T X` | 直接写 `ctx` 被读成 "cats"；逐字母后回听为 "CTX" |
| `dsh-shell` | `D S H shell` | `dsh` 被读成 "dish"；逐字母后为 "DSH" |
| `pwsh` | `P W S H` | 被读成 "process" |
| `ctx.get` | `C T X 点 get` | 点号用「点」读（同文件名规则） |
| `ctx.llm` / `ctx.shell` / `ctx.credentials` | `C T X 点 …` | 同上 |
| `ctx.browserUse` | `C T X 点 browser use` | 驼峰 `browserUse` 被读成 "berber use"；拆词后正常 |

## 驼峰 / 复合词

| 屏上写法 | 口播写法 | 原因 |
|---|---|---|
| `ShellExecutor` | `Shell 执行器` | 写成 `ShellExecutor` 或 `Shell Executor` 都被读成 "Shell Executive / Exactor" |
| `LocalBashExecutor` | `Local Bash 执行器` | 同上 |
| `sandboxMode` | `sandbox mode` | 拆词后回听正确 |
| `sandboxPolicy` | `sandbox policy` | 同上 |

## 全大写 / 英文词

| 屏上写法 | 口播写法 | 原因 |
|---|---|---|
| `PENDING` | `pending` | 全大写被拼读成 "pinned in ding ding"；小写按词读正常 |
| `subprocess` | `sub process` | 连写被读成 "sub-price-price"；拆成两个词后为 "sub-process" |
| `devDependencies` | `dev dependencies` | 连写被读成 "DFD Pandencies"；拆词后正常 |
| `cordis` | `C O R D I S` | 连写被读成 "Cortist"；逐字母后为 "CORDIS" |
| `capability seam` | 删掉英文，只留「接缝」 | `seam` 被读成 "sim"；屏幕上仍显示英文 |
| `schemastery` | 删掉，说「运行期依赖只有一个」 | 被读成 "Skemmestory"；屏幕上 package.json 里有真名 |

## 保持不变（实测正常）

`shell` / `bash` / `bash-local` / `bash-sandbox` / `Service` / `Definition` / `Context` / `extends` / `super` / `inject` / `import` / `peer` / `execute` / `unavailable` / `subprocess` / `Cordis`（听感接近 "Cordes"，可接受）。

## 规矩

1. 改稿只改**口播与字幕**用的 `SCRIPT.md`；屏幕上（frames）仍用仓库真名。
2. 一句里英文缩写不超过两个，否则句子会被读成串字母。
3. 新片开工前先按本表建自己的读法规则，再合成。
4. 合成后跑 `make listen`：它把必须用、又只能靠耳朵判定的词（接缝 / 重写 / 重名）连同时间点和试听命令列出来。
