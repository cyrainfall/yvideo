## Frame 1 — 手在谁那里

上一集拆到一半：一轮对话里，有个东西还没有打开。
工具。
模型只会说一句话：跑一下测试。它自己跑不了。
真正动手的，是 harness 里那张注册表。
模型写一条调用，harness 找到实现，跑完把结果写成一条消息，还给它。
这条来回，就是这一集要拆的东西。

## Frame 2 — 算出来的菜单

工具不是写死在循环里，和插件同一个来路：注册进来的。
注册的时候可以写在全局，也可以写在某个 agent 名下。
近的盖住远的：同一个名字，子 agent 能换成自己的实现。
还能再收窄：allow 和 deny 只对全局工具生效，逐层求交，取最严的那层。
所以每次请求之前，模型拿到的不是仓库里所有工具，是算出来的那张菜单。
工具目录里，37 个包，76 个名字。
而这一份会话，模型只用了 6 个。

## Frame 3 — 三段

一次调用进来，先过第一段：pre-execute，一个瀑布。
每个监听者都能交出四种决定：放行、拒绝、取消、问人。
然后是一层守卫。
守卫只有两种返回：拒绝，或者不管。它没有放行这个选项。
顺序再怎么排，也翻不回允许。
再往下是第二段：execute，一层环绕分发。
超时、指标都挂在这里，工具本身不用知道。
工具自己的 execute 在最里面。
跑完是第三段：post-execute。

## Frame 4 — 可谈判的，和不可谈判的

把这四种决定和那层守卫摆在一起，会看到一个不对称。
pre-execute 是可谈判的：它能放行，能拒绝，也能问人。
问人不是弹窗，是交给 approval 服务。
没有这个服务，或者没人能回答，问就等于拒绝。
子 agent 派出去的时候，审批策略被直接钉成 never，它的 ask 必然失败。
守卫不可谈判：只有拒绝和不管。
沙箱就长这样：只读、只写工作区、完全放开。
被拒的调用可以申请一次升权，但升权又是一次 ask，于是又回到那条会失败的路径。

## Frame 5 — 结果不是终点

工具返回的值，不是模型看到的东西。
执行完先过 post-execute：接受、改写内容、接一段上下文，或者整条驳回。
驳回不是静默失败，它变成一条带错误的结果，内容就是纠正意见。
模型看到理由，才知道下一步改哪里。
最后还有一道 finalizeContent：同步，只能动内容，跑在快照之前。
再往后 tools/result 上的人看到的，已经是一份冻结的结果。

## Frame 6 — 真跑一次

真跑一次。还是那一份会话。
481 次工具调用，6 个工具，352 次是 bash。
中位数 54 毫秒，305 次在一百毫秒里就结束。
也有慢的：19 次超过一分钟，最长的一次等了 152 秒。
三次调用带着错误回来：找不到任务、读不到图、交付的文件不存在。
它们没有抛异常，都变成了一条结果，回到模型手里。
还有一次调用，快照定格时还没有结果——那一轮还在跑。

## Frame 7 — 手可以换

所以这只手可以换。
bash 后面是 shell 服务，文件工具后面是文件系统服务，再往后是隔离服务。
隔离拆成四个包：隔离的约定、本机后端、策略解析，还有一个 Windows 专用后端。
Linux 上用 bwrap，macOS 上用 Seatbelt。
换成容器、microVM 或者远程执行器，换的不是某个工具，是整条能力。
下一集，我们给自己装一只手上去。
