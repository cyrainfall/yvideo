## Frame 1 — 上一集留了个问题

上一集，树上的每个节点，都是一个 apply。
可这棵树，是谁拼出来的？
没有一个文件，写着完整的它。

## Frame 2 — profile 与 bundle

它由两样东西拼出来。
profile，是一个具名组装，web、headless、sdk，都只是名字。
bundle，是可以再被上层改的分发格式。
两边都靠 package.json 里的一个字段，自报家门。

## Frame 3 — 四层，从下往上

空列表上，一层一层压。
profile 列出的 bundle，按顺序先来。
然后是 profile 自己的 patch。
再是 home 目录里的那一份。
最后，是你命令行临时给的 overlay。
同一个 id，后写的赢。

## Frame 4 — patch 只做两件事

patch 的语法很小，只做两件事。
按 id 找到一条，把它的整个 config 换掉，不是合并。
或者 insert，插一条原本没有的。
所以想改一个字段，你得把那一整块，重新写一遍。

## Frame 5 — 真跑一次

真跑一次，看它长出什么。
web profile，三千四百九十一行，二百三十五条。
第一层是 dsh-base；
六百二十八行起是 web-app；
再往下，是装进来的插件；
到三千四百六十行，才轮到 profile 自己。

## Frame 6 — 改一行会怎样

所以一次改动，很便宜。
配置会被重新载入，只载入变了的那一条；模块根默认不动。
想试一条又不想留下，用 --patch 临时盖在最后。
长期要留的，写进 profile 的 patch；一次性的，别写。

## Frame 7 — 树是叠出来的

这棵树不是写出来的，是叠出来的。
每一层都能单独读、单独改、单独撤。
你自己那一层，只有你动过的那几行。
