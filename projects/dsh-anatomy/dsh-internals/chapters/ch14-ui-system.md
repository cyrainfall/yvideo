# 第 14 章：UI 设计与样式系统

## 核心思想

DSH 的视觉判断有两条独立要求：组装后的整页或整弹窗要清楚表达元素之间的关系，同时每项实现要符合所属规范。对齐与空间分组是基础要求，不是 token 检查通过后的可选打磨；反过来，token 合法也证明不了相邻角色与嵌套轮廓协调。样式系统（谁拥有数值）与审查系统（谁判断关系）因此必须同时成立。

## 框架与方法

- **整页或整弹窗是审查单位（whole-interface review）**：选择参照和判断关系时，把整个页面或弹窗当作一个视觉整体。
  - 何时用：明确要求的完整界面审查；日常改动也以此为构图参照，但只审受影响的分组与跨组关系。
  - 怎么做：弹窗把标题、关闭按钮、全部内容分区、滚动区域和底部操作一起纳入，页面把导航、页头、工具栏、内容区和固定操作一起纳入，滚动后才看到的内容仍属同一整体。对齐与居中的参照取页面或弹窗自己的边缘——打开的弹窗在底层页面之上形成自己的构图。先看整体构图，再按「内容描述什么、操作什么」划语义组，先比较相邻组、再看组内元素。

- **三条件判据与四态记录**：一条关系成立，至少要同时满足三项——结构使用同一个参照；实际画面表达出该关系；改变相关内容或状态后仍然成立。
  - 何时用：判定某个发现是缺陷还是错觉时。
  - 怎么做：测试断言存在、共用同一个 token、截图成功、单张裁图，都不能单独替代这三项。优先级按误导程度、使用频率与传播范围排序，不能用「只差几像素」排除高频错列。结论分四态记录：「已检查无新增问题」「已修复并复查」「发现但未修复」「未检查」。

- **规则归属表（rule owners）**：圆角与嵌套几何归圆角规范；语义色、字号行高配对、发丝线、层级阴影、菜单材质、动效归 Web 样式参考；组件复用与反馈归属归客户端 UI/UX skill；空间分配与焦点归响应式 skill；图案归官方图案 skill；失败可见性归错误处理 skill。
  - 何时用：不确定某条判断该由哪份规范裁决时。
  - 怎么做：当前仓库的所有方及其明确记录的例外，优先于旧版个人 skill 或外部案例；用户的具体选择只适用于指定组件族，不会默默替换全局体系；实现与规范不一致时报告差异，不能把既有代码自动当成新规则。

- **圆角选择顺序（role → size variant → nesting → curve）**：先确定组件用途，再确定尺寸变体；宽度、文字长度、偶发换行和内容展开都不单独决定使用更大的圆角。
  - 何时用：新增组件、复用变体、审查几何时。
  - 怎么做：`H` 是以 CSS 像素计、包含边框的设计外部高度，`R` 是浏览器压缩相互重叠圆角之前的 CSS `border-radius`。用途定档后用公共尺寸变体兜边界：高卡片仍是卡片，不因高度超过按钮就升到 R28；专门设计为多行的 cell 用 R16，普通按钮文字换行时仍保留按钮变体。填充、描边、ghost、加载中和禁用变体保持相同尺寸与圆角；hover、按下、选中、焦点不改变圆角。

- **三种嵌套关系（nested geometry）**：修改子元素圆角前，先判断它属于哪一种关系。
  - 何时用：任何「内层要不要减掉外层」的判断。
  - 怎么做：圆弧同心内缩时 `内层 R = max(0, 外层 R − 内缩距离)`，两段圆弧同心且都用 `round`；底色紧贴容器边缘时由外框决定可见圆角，裁切或继承相应圆角；容器内独立的卡片或表单组按自身用途选档，不机械减去全部父级内边距。半径相减也用于嵌套超级椭圆的名义尺寸关系，但相同指数不意味着两条曲线严格等距，对角间隙可能不同于侧边内缩——要求径向严格等距时改用圆弧。

- **状态语义（state semantics）**：选中表示「当前所在项」，悬停表示「指针在这里」，焦点表示「键盘输入作用于这里」，禁用表示「这个操作暂不可用」。
  - 何时用：检查叠加状态与相邻条目时。
  - 怎么做：选中行旁出现另一条悬停行，与同一行的选中＋悬停同等重要。通用 hover 底色不能抹掉当前状态，焦点提示不能融进选中样式，淡化后的禁用不能看起来像取消了选择。背景绘制只是线索之一，还要结合当前行语义与浮现的操作；选中与悬停不必用不同颜色。

- **样式职责归属（ownership）与两条互斥的描边路线**：`ui-theme` 拥有 `--dsw-*` 静态色阶、语义别名、排版、动效、渐变、阴影与明暗主题偏好，`ui-layout` 把解析后的主题快照应用到文档；功能包只用语义别名，不得另定义全局主题。组件样式以 CSS Modules 放在组件旁，共享值归主题包。
  - 何时用：要新增颜色、圆角、阴影或动效时。
  - 怎么做：先复用 `ui-primitives` 组件目录——它是唯一跨功能包的通道，有意的视觉差异应作为那里的一个 prop 而不是另起拷贝；用 CSS Modules 加 `clsx`，不引入组件库或 Tailwind，不写颜色字面量。描边只有两条路线：平面中性边框与分割线一律 `0.5px` 发丝线；高层级表面（菜单、浮层、对话框、面板、悬浮按钮、输入框）设 `border: 0` 并用 `--dsw-elevation-*`，其阴影已含发丝描边。两者不得叠加。

- **输入能力查询（input capabilities）**：`pointer` 与 `hover` 描述浏览器选定的主指针，`any-hover` 考虑所有可用指针，三者都不检测物理键盘。CSS 悬停留在 `(hover: hover)` 内且不依赖视口宽度，选中、展开、按下、键盘焦点样式留在条件之外；JavaScript 悬停预览用 `(any-hover: hover)` 接受 mouse 进入、忽略 touch 进入。

## 关键概念

- **审查单位**：整页或整个弹窗，提供构图参照并界定「同一种关系」的比较范围。
- **影响范围（review scope）**：一次改动需要检查哪些关系，由改动本身决定，不由示例清单决定。
- **关系清单**：语义组加上需要比较的关系（父子缩进、跨分区文字列、重复操作槽、字段与校验、滚动内容与固定操作）。
- **发丝线（hairline）**：中性 `0.5px` 边框与分割线，Chromium 绘制为一个设备像素。
- **层级阴影（elevation）**：`--dsw-elevation-panel` / `prominent` / 输入框专用 `soft` 材质，第一层投影即发丝描边。
- **超级椭圆（superellipse）**：主题在支持的引擎上通过 `corner-shape: superellipse(1.5)` 应用的曲线；`corner-shape` 不继承，主题把它应用到元素及 `::before`/`::after`。
- **`corner-shape: round`**：正圆与胶囊必须配对声明的曲线，使 `50%`/`100%`/胶囊半径保持圆弧。
- **语义别名（`--dsw-alias-*`）**：功能包唯一允许使用的颜色层，静态色阶不可直接引用。

## 心智模型

- 当发现「只差几像素」时，先问这个错列的出现频率与传播范围；差值小不是排除理由。
- 把 token 检查看成「数值属于尺度」的证明，而不是「相邻角色协调」的证明。
- 把 hover 底色看成轮廓的一部分：改了底色就等于改了可见轮廓，即使静止时描边完全正确。
- 把圆角决策看成角色问题而非几何问题：先问「这是什么」，再问「多大」。

## 反模式

- **所有元素套同一个圆角**：合法 token 也能组合出不协调的外观；一致指相同角色、相同尺寸变体遵循同一规则。
- **给贴边拼接的每个子元素四角都加圆角**：造成缺口、月牙或双轮廓；外框应拥有暴露的角落。
- **只对齐图标大小或卡片外缘**：文字起点仍可能不同，要合计各表面的 border、padding、前导槽与 gap。
- **在 `(hover: hover)` 之外写悬停样式，或按视口宽度判断悬停**：触屏布局会拿到无法退出的 hover 态。
- **拿 fixture 截图或组件测试数量当作整页通过**：fixture 只覆盖它渲染的条件。

## 代码/配置示例

分体式引导卡片：外层拥有共享圆角与裁切，贴边内部按钮保持直角。

```css
.entry {
  border-radius: var(--dsl-guide-entry-radius);
  overflow: hidden;
}

.main,
.trigger {
  border-radius: 0;
}
```

设置卡片共用一套默认材质，明暗主题都通过别名解析：

```css
.card {
  border-radius: var(--dsw-radius-xl);
  border: 0.5px solid var(--dsw-alias-settings-card-stroke);
  background: var(--dsw-alias-settings-card-fill);
}
```

悬停写在能力查询里，状态样式留在外面：

```css
@media (hover: hover) {
  .row:hover { background: var(--dsw-alias-bg-hover); }
}

.row[aria-selected='true'] { /* 选中不依赖 hover 条件 */ }
```

## 参考表

圆角档位：先按用途选，再按尺寸变体兜边界。

| 用途 | 典型尺寸或示例 | 圆角 | 共享 token |
|---|---|---|---|
| 小细节 | 低于 H20；键帽、行内代码、微型控件 | R4 | `--dsw-radius-xs` |
| 紧凑控件 | H20–28；小按钮、紧凑图标按钮、紧凑菜单项 | R8 | `--dsw-radius-sm` |
| 标准控件或单行 cell | H32–40；按钮、输入框、选择器、导航行 | R12 | `--dsw-radius-md` |
| 大控件或分组内容 | 大按钮、明确设计为多行的 cell、嵌套表单组 | R16 | `--dsw-radius-lg` |
| 独立内容卡片 | 设置卡片、消息气泡、引导入口卡片 | R20 | `--dsw-radius-xl` |
| 主容器 | 对话输入框、对话框、主面板或悬浮面板 | R28 | `--dsw-radius-panel` |

三种嵌套关系：

| 关系 | 规则 | 示例 |
|---|---|---|
| 圆弧同心内缩 | 内层 R = max(0, 外层 R − 内缩距离)；两段圆弧同心且用 `round` | 外层 R16、内缩 4、内层 R12 |
| 底色紧贴容器边缘 | 由外框决定可见圆角；裁切底色或继承相应圆角 | 两个独立 hover 区域组成的分体按钮卡片 |
| 容器内独立卡片或表单组 | 按子元素用途选档；不机械减去全部父级内边距 | R20 设置卡片内的 R16 编辑器 |

状态叠加时必须保留的含义：

| 组合 | 必须继续可辨 | 典型错误 |
|---|---|---|
| 已选中＋另一行悬停 | 当前所在位置仍可识别 | 临时悬停行比当前行更像选中 |
| 同一项已选中＋悬停 | 选中保留，同时有交互反馈 | 通用 hover 底色抹掉当前状态 |
| 已选中＋键盘焦点 | 当前位置与键盘目标均可区分 | 焦点提示融进选中样式 |
| 已选中＋禁用 | 保留的选择与暂不可用同时可辨 | 淡化后看起来像取消了选择 |
| 展开＋菜单打开 | 当前操作有明确归属 | 面板高亮与行高亮无稳定关系地竞争 |

## 实例演练

场景是一份预览页头：上排是面板控制，下排是文件显示控制与「在应用中打开」分段按钮。两排属于同一个预览页头，每排又包含作用范围不同的操作。

第一步定范围。这是局部改动，审查单位是该页头所在的整页——路径、标签页与内容边缘一起看，但不遍历全产品；跨组关系只有一条主线：两排控件的尾端。

第二步先建尾端关系。按上排的图标框与下排的完整控件比较尾端，保留图标内部留白；不要直接对齐额外热区，也不追齐单个 glyph 的像素边缘。判据是三条件的第一条：两端共用同一个参照。

第三步收组。把显示控制收成一组，与外部打开操作分开；分段按钮按完整单元处理，不把它的箭头与无关的面板操作共用列轴。

第四步处理可见间距与行为。组件内部可能已经居中，组装后仍会出现无关的右边距、高度和分组间距；缩小分段按钮的外部宽度，可以在保留前方图标列轴的同时让可见间距相等。随后检查两个分段的点击区域，以及边框对布局尺寸的贡献——只比可见边缘会漏掉边框占位；用一排独立图标替代分段控件无效，因为被验证的对象变了。

第五步回整体并记录。保留长路径与窄面板两种内容，把两排一起观察；窄面板下重排完整语义组，而不是缩小所有字号。结论按四态交付：「两排尾端已修复并复查；长路径与窄面板已检查；未检查触屏悬停预览」。

## 关键要点

1. 先定审查单位与影响范围，再开始判断；示例清单不决定范围。
2. 一条关系要过三条件：同一参照、画面可见、状态变更后仍成立。
3. 圆角按角色选档，不按高度选档；嵌套先判三种关系再算数值。
4. 平面边框用 0.5px 发丝线，高层级表面用 elevation 且 `border: 0`，两者不叠加。
5. 功能包只碰语义别名与组件旁 CSS Modules；共享值改动落在 `ui-theme`。
6. 悬停写在 `(hover: hover)` 里，键盘焦点不依赖能力查询。
7. 结论分四态交付，并写明未检查的区域与状态。
