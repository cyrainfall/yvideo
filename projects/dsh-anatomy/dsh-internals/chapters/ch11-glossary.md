# 第 11 章：术语表与词汇纪律

## 核心思想

DSH 的领域词汇为每个概念规定一个规范术语，术语表真正的用途不是查定义，而是阻止两种偷懒：用一个词覆盖多个角色，或用一层结构去表达另一层的事实。`seam`、`scope`、轮次、`Round`、目标、Ralph 这几组词一旦混用，讨论的对象会在不知不觉中换掉，结论随之失效。词汇纪律就是让「角色」「层级」「所有权」始终分开表述。

## 框架与方法

- **一概念一术语（one canonical term per concept）**：术语表为每个概念保留唯一规范词，并明确该词只保留此义；能力成员应按其角色、类、服务、约定或扩展点命名，不借用更高层的词。
  - 何时用：写文档、起包名、开 issue、做 review 时，任一概念第一次落地。
  - 怎么做：先判断这句话说的是「角色」「层级」还是「所有权」，再取对应术语；如果术语表里找不到合适的词，说明你在造新概念，应先补定义而不是就近借一个词。

- **seam 的三角色分解（Service Definition / Service Provider / Consumer）**：seam 是一种*可替换能力*的整体，不是它内部的任何一方。它包含拥有自身 `ctx.<key>` 与词汇类型的 Cordis `Service`（Service Definition）、一个或多个 Service Provider，以及一个或多个注入该服务的 Consumer。
  - 何时用：描述一个可替换能力时；判断某个包在能力里站哪个位置时。
  - 怎么做：把三方名字都写出来，句子仍然成立才算说对了。`packages/shell` 是规范范例：`dsh-shell` 是 Service Definition，`dsh-bash-local` 与 `dsh-bash-sandbox` 是提供方，`dsh-tool-bash` 是 Consumer。Service Definition 必须是 Cordis `Service`——可以是 `ShellExecutor` 这样的抽象类，也可以是 `WebRuntime` 这样的具体注册表，绝不是 TypeScript `interface`。角色需要独立演进时通常分处不同包，但同一关注点下，一个包也可以承担多个角色，例如 `dsh-user-approval` 在同一个包里既是 approval seam 的 Service Definition，又是它的具体实现。

- **scope 只做扁平两层可见性**：一项贡献（工具、提示词段、变量、限制、监听器）要么是全局的，要么归属于恰好一个 scope key。只有两层，没有向下继承。
  - 何时用：讨论「某个 agent 能不能看到/调用某个东西」时。
  - 怎么做：先确认这条注册挂在哪个 scope 上。带作用域的注册不会向下继承给 subagent；想表达子树行为，用 `lineage` 的数据，不要改 scope 结构。`agent.ctx` 上的注册同时决定两件事——scope 可见性与生命周期绑定到该 scope——因为它们是同一个事实。

- **lineage 只做数据**：父子关系以数据形式携带（`parentSession`、持久的 `delegationDepth`、运行时 `subagentDepth`），从不影响可见性。
  - 何时用：需要知道「谁是谁的子会话」时。
  - 怎么做：从这三个字段读事实；不要指望它们改变任何过滤器。scope 决定看得见什么，lineage 只记录血缘。

- **循环三层分离（轮次 / 步骤 / `Round`）**：轮次（turn）是会话中一次对已接纳输入的排空；步骤（step）是一次模型请求及其引发的工具执行；`Round` 是承载一个轮次的外层策略迭代，例如一个 Goal Round 或一次使用全新 agent 的 Ralph 尝试。
  - 何时用：讨论「跑了几轮」「这次请求算第几步」「上限怎么算」时。
  - 怎么做：先问这个计数归谁所有。`Round` 计数器归策略所有，并不统计会话中的每个轮次；一个轮次包含零个或多个步骤。

- **目标（goal）是状态，不是调度器**：目标是附着在现有会话上的单个持久完成目标，带按修订号演进的 `active` / `paused` / `blocked` / `complete` 阶段与 Goal Round 上限；`blocked` 保留策略代码与说明；会话日志仍是其真源。
  - 何时用：解释「agent 为什么自己继续干活」时。
  - 怎么做：把自动工作拆成两件独立事实——持久的目标状态，以及进程本地的目标激活（`armed` / `disarmed`，有意不参与持久回放）。恢复或 fork 之后，只有随后通过 `/goal` 或模型工具执行一次经人类授权的恢复变更，自动工作才能开始。

- **Ralph 是原语组合，不是一种模式**：Ralph 循环是一次面向不可变目标的前台全新 agent 工作流运行，由工作流与 subagent 原语组合而成，是面向模型的工具策略。
  - 何时用：区分「同会话目标续行」与「每次换新 agent 重跑」时。
  - 怎么做：看是否需要跨 `Round` 传递有界的 Ralph 交接（状态、摘要、证据、后续步骤、阻塞说明）。Ralph Round 不接收父会话或此前子会话的对话种子，跨 `Round` 的状态靠共享工作区加这份交接，且交接补充工作区而不取代其权威地位。

## 关键概念

- **seam**：包含 Service Definition、Service Provider、Consumer 三种角色的可替换能力整体，不是其中任一角色。
- **scope**：按 agent 划分的注册单位，只有全局与带作用域两层，扁平不继承。
- **scope key**：scope 的不透明标识，按对象同一性比较；harness 约定一个活跃的 agent 就是其自身 scope 的 key。
- **scope carrier**：scope 过滤分发携带的 `thisArg`（由 `scopeTarget` 构建），放行无标签监听器加主体自身监听器；无主体 carrier 只放行无标签监听器。
- **scoped dispatch**：关于某个 agent 的活动的事件用该 agent 的 carrier 分发；关于注册表本身的事件属注册表主体事件，保持不过滤。
- **setup window**：创建者组装 agent 作用域环境的创建时隙（`CreateAgentOptions.setup`），只做注册，从不驱动 agent。
- **轮次（turn）**：会话中一次对已接纳输入的排空过程。
- **步骤（step）**：一次模型请求以及由模型响应引发的工具执行。
- **交互段（exchange）**：从首个「步骤接纳真人输入」的轮次起、到下一个这样的轮次为止的连续轮次；被通知唤醒的轮次归入前面的交互段。
- **人类命令**：以斜杠开头、由面向人类的适配器经 `ctx.commands` 解释执行的指令，不会成为模型消息。

## 心智模型

- 当想说「subagent 继承了带作用域的工具」时，改说「scope 注册扁平两层、不向下继承；父子关系由 lineage 数据表达」——可见性与血缘是两套事实。
- 把 scope 看成一页注册簿、把 lineage 看成户口本：一页纸决定看得见什么，户口本只记录谁是谁的孩子。
- 当一句话里的「round」其实指会话里的一次往返，说明你该说「轮次」；`Round` 留给拥有它的那层策略。
- 把 seam 看成一份三方合同：定义方、提供方、消费方都在合同上，任何单独一方都不是合同。

## 反模式

- **用 seam 指某个角色**：说「seam 实现了 shell」会把能力整体当成实现主体，之后讨论替换、演进、责任归属时全部失焦。
- **用 scope 结构表达子树行为**：一旦给 scope 加上继承，就同时改掉了生命周期绑定与分发过滤两件事，而这些本该由 lineage 数据加各自的注册解决。
- **把 `Round` 当轮次计数器**：`Round` 归策略所有，用它统计会话轮次会让上限计算和实际排空次数错位。
- **把目标当调度器或独立会话**：目标是状态，真源在会话日志；把它当调度器后，就无法解释为什么恢复或 fork 后自动工作需要人类重新授权激活。
- **把 Ralph 当 agent loop 模式或通用工作流脚本功能**：它是工作流与 subagent 原语的组合；按模式理解会漏掉「新 agent、无对话种子、有界交接」这三个约束。
- **把命令输出当持久领域**：命令平面负责发现、解析、分发、取消与结果渲染，除非处理器另行改变持久领域，命令输出属于 UI 状态。

## 代码/配置示例

三个角色三份名字，用注释标注，避免一个词概括整条能力：

```text
ShellExecutor        // Service Definition：拥有 ctx.shell 与词汇类型（抽象类）
dsh-bash-local       // Service Provider：本机实现
dsh-bash-sandbox     // Service Provider：沙箱实现
dsh-tool-bash        // Consumer：注入 ctx.shell，向模型暴露工具
```

两类事实分开表述：

```text
scope   → 可见性：全局 或 恰好一个 scope key（扁平，不继承）
lineage → 事实：parentSession / delegationDepth（持久） / subagentDepth（运行时）
```

## 参考表

循环、目标与策略的层级归属：

| 术语 | 计量单位 | 由谁推进/拥有 | 不是 |
|---|---|---|---|
| 步骤 step | 一次模型请求 + 其引发的工具执行 | 模型响应 | 不是轮次 |
| 轮次 turn | 一次对已接纳输入的排空 | 模型与工具停止工作，或终止策略介入 | 不是外层策略迭代 |
| 交互段 exchange | 连续轮次，从首个接纳真人输入的步骤起算 | 下一个这样的轮次 | 不是 `Round` |
| Round | 外层策略迭代 | 拥有该 `Round` 的策略 | 不统计会话中的每个轮次 |
| Goal Round | 当前目标接纳的一次续行周期 | 同会话驱动器（具体化为一个由目标触发的轮次） | 不是人类轮次；无关人类轮次不消耗其上限 |
| Ralph Round | 一个全新子会话 | Ralph 循环 | 不接收父会话或此前子会话的对话种子 |
| 目标 | 附着在现有会话上的单个持久完成目标 | 人类授权的变更与修订号 | 不是调度器，也不是一段独立对话 |

易混说法的替换判据：

| 容易出现的说法 | 应改说 | 判据 |
|---|---|---|
| 「seam 实现了 shell 能力」 | 「`dsh-bash-local` 是 shell seam 的 Service Provider」 | seam 是能力整体，不能充当实现主体 |
| 「subagent 继承了带作用域的工具」 | 「scope 扁平两层、不向下继承；父子关系是 lineage 数据」 | 可见性归 scope，事实归 lineage |
| 「这个 Round 里跑了三次轮次」 | 「一个 Goal Round 具体化为一个轮次，其中含零个或多个步骤」 | `Round` 归策略，轮次归会话 |
| 「goal 在后台调度任务」 | 「目标是状态，会话日志是真源」 | 状态与调度器分离 |
| 「Ralph 是一种 agent loop 模式」 | 「Ralph 循环是由工作流与 subagent 原语组合的面向模型工具策略」 | 组合关系，不是运行模式 |
| 「执行一个 shell 命令」与「调用工具」混称 | 人类命令走 `ctx.commands`，shell 命令走 `ctx.shell`，工具面向模型 | 适配器与受众不同 |

## 实例演练

目标：让一个 agent 拥有一个只在它自己范围内可见的工具变体，同时让另一个全局工具对它不可用。全程只用术语表允许的词。

第一步，选层。这条注册属于「带作用域」而不是全局，因为它只对一个 agent 成立。注册点选在 setup window（`CreateAgentOptions.setup`）：此时 scope 与 agent 对象已存在，但 agent 或会话尚未发布，`agent/created` 尚未触发，首次提示词尚未组装。setup 只做注册，从不驱动 agent——这正是它被选中的原因。

第二步，处理同名。如果该工具与一个全局工具同名，触发 shadowing：带作用域的版本仅在该 scope 内替换同名全局对应项，最具体者胜出。这也是按 agent 定制工具变体的机制，不需要复制一份全局注册。

第三步，处理「不可用」。要让另一个全局工具对它消失，用 restriction（`tools.restrict`）：它为单个 scope 过滤全局工具集合，多个 restriction 取交集组合；scope-local 注册在过滤之后合并。被过滤掉的全局工具既不出现在提示词中，也拒绝执行，与不存在的工具无法区分——所以不要指望从报错里分辨「被限制」和「没这个工具」。

第四步，检查子代理。此处最容易出错：该注册不会向下继承。子代理需要同一能力时，必须在它自己的 setup 里注册；如果实现只关心「谁是父、谁是子」，那就用 lineage 的三个字段读事实，不要试图用 scope 结构表达。

第五步，复查用词。写变更说明时不要出现「子代理继承了该工具」；正确表述是「该 scope 注册对子代理不可见，子代理在自己的 setup 中独立注册」。同一句话里既说清了可见性来源，也没有把血缘混进可见性。

## 关键要点

1. 说一个能力时，先写出 Service Definition、Provider、Consumer 三方；写不全说明你其实在说某个角色。
2. 可见性只归 scope，血缘只归 lineage；任何「继承」的说法都要先被这两条否掉一次。
3. 轮次、步骤、`Round`、Goal Round 各有归属者，计数前先问「这个计数器是谁的」。
4. 目标是状态、会话日志是真源、激活是进程本地权限；三者不能互相替代。
5. `Ralph` 用「新 agent + 无对话种子 + 有界交接」来识别，不要用「循环」这个词去识别。
6. 被 restriction 过滤的工具与不存在的工具不可区分，这是设计而不是缺陷，讨论时要说明。
