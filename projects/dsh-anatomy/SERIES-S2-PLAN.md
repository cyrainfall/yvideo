### 弧 A · 语法

#### S2E01（EP07）接缝：两百个插件，为什么没长成意大利面（插件架构 / capability seam）

- **问题**：一个"一切皆插件"的仓库，凭什么插件越多越有序？
- **答案链**：插件多 ≠ 随便挂，一个能力要**三角色齐全**才算数——声明契约的 Service Definition（拥有 `ctx.<key>`，是**抽象类**不是 TS interface）+ 一个或多个 Provider + 只认定义不认实现的 Consumer → 规范范例 `dsh-shell`（定义）+ `bash-local` / `bash-sandbox`（这台机器装的是 Bash 的两个；沙箱那个**继承**本地那个再改执行世界，不是重写抽象类）+ `dsh-tool-bash`（消费方，另有 `tool-pwsh` 第二个消费方）→ 换一个 Provider 就换一种产品（`bash-sandbox` 多注入 `sandbox` / `sandboxPolicy`，工具层一字不改）→ 注册形态先于实现选定：命名注册表（`ctx.llm`）、单槽（`ctx.browserUse`）、有序尝试（认证链，**传输层** seam）、每上下文一实例（`ctx.shell`：没有注册表，只有一个名额）、注册即绑定（`ctx.credentials`）→ 判据：消费方依赖的是**定义包**（peer），两个提供方都不在运行期依赖里 → **缺席分两种**：硬 `inject` 缺席=停摆（PENDING），可选 `ctx.get` 缺席才是 `unavailable` → 重复加载抛错是 cordis 的标准行为，不是包自己的守卫。
- **现场演示**：三段串联——①`cordis_inspect` 取 `shell` 活体合约（`access` 双通道 + "loading a second throws"）②`Config.listConfigs` 看插件行（本机 `bash-sandbox` 在列、`tool-bash` 为 `inactive`）③源码 file:line 钉死装配。**不能一屏指认三角色**（服务目录不记 provider 归属）。备胎：合约 + `FACTS.md` 表两段。
- **证据**：ch02、ch11、`patterns.md` 注册形态五选一、`glossary.md` capability seam；上屏前以 `episodes/ep07/FACTS.md` 为准（含三处措辞修正）。
- **钩子**：消费方不 import 提供方，那插件之间怎么"听见"彼此？→ 事件。

#### S2E02（EP08）事件的三张地图：插件之间怎么说话（事件总线 / waterfall）

- **问题**：几十个插件协作，为什么没有 import 地狱？
- **答案链**：事件分三域，各有用途——会话事件（`session/event`）是持久事实、重载后仍在；Agent 事件（`agent/*`）是实时协调、重载即失；能力事件（`fs/*`、`tools/*`）让人不引入 import 循环就能往 seam 上加策略 → 分发模式是公开契约：`emit` 旁听、`waterfall` 可改写必须 `next()`、`serial` 首个非空截断、`parallel` 扇出、`bail` 授权短路 → **bail 全库只有一处**（`webserver/authorize`），因为单方短路整条路径太危险——稀缺本身就是设计 → 观察型 waterfall 监听器不调 `next()` = 静默否决，不报错。
- **现场演示**：两连发——①仓库真实事件生产者/消费者矩阵数格子；②一个最小插件"忘 `next()`"复现静默失效（demo 收据）。
- **证据**：ch06、ch18、ch23、`cheatsheet.md` 分发模式表。
- **钩子**：事件挂上了，插件挂错了会怎样？→ 生命周期。

#### S2E03（EP09）可逆的世界：热重载凭什么不漏（热重载 / 插件生命周期）

- **问题**：改一行配置就重挂载，凭什么不多出一份回调？
- **答案链**：插件加载期间建立的都是 **effect**，注册带回卸载函数（disposer），卸载**逆序**清理——有顺序依赖的几步必须并进同一个 disposer 依次 await → 硬依赖写 `inject`，不满足就停在 **PENDING**；`dsh-tools` 与 `dsh-system-prompt` 必须成对，缺一个=静默 PENDING → Config 双重身份（TS 接口 + 运行时 schema，普通对象直接失效）与三态（`rawConfig` / `effectiveConfig` 激活前 undefined、卸载后仍可读 / `resolveConfig()` 试算）→ 热更新字段走 `.volatile()`，读到值只在本操作内有效 → HMR = 卸载旧实例再加载新代码，裸 timer 不进 `ctx.effect()` 就一轮多一份回调。
- **现场演示**：**全季最漂亮的对照实验**——同一插件两个版本，裸 timer 版热重载三轮计数器 1→2→3，effect 版 1→1→1（改造 `demo/greet/` 即可，可行性高）。
- **证据**：ch16、ch24、ch19、ch22、`cheatsheet.md` 气味表首三行。
- **钩子**：语法讲完了。现在把镜头转向干活的——一个 agent 怎么变成一队 agent。

### 弧 B · 深水区

#### S2E04（EP10）一台机器的五个刻度：多智能体怎么编（多智能体 / subagent 编排）

- **问题**：委派、团队、计划、目标、待办——是五个功能，还是一台机器？
- **答案链**：是一条**栈**：委派决定谁执行、团队决定多执行者怎么共享、计划约束当前轮次、目标约束跨轮次，待办只是贯穿全栈的最小账本 → 委派的路由开关是"方法在不在"：带 `prepareContinuable` 的提供方跑本地可继续子代理，只有 `start` 的跑一次性外部子代理 → 团队共享任务用 **CAS 不用锁**：每条变更存完整快照、`revision` 每获准变更 +1、`blockedBy` 必须无环；`writeScopes` 只是提示不是锁 → 子级失败不是异常是 **`stopReason`**：completed / aborted / error / max-tokens / refusal，`result` 不因子级失败 reject → 计划是软性指引：`plan/mode` 只进日志**永不进 transcript**，硬限制在沙箱与审批 → 目标是"两套状态叠一个修订号"：`GoalPhase` 持久可回放，activation 进程本地永不持久，`blocked` 是唯一"因问题而停"的持久状态。
- **现场演示**：真开一次委派（本机 DSH 现成的 subagent 树），收 `list_agents` 与 goal/团队事件收据——本系列就是在被讲解的系统里做出来的，这句实话本身就是素材。
- **证据**：ch29（已全文核对）、`glossary.md` Goal Round / Ralph handoff。
- **钩子**：一队 agent 各说各的话——流回来的字节长什么样？→ 流式。

#### S2E05（EP11）token 的河道：一次回复在代码里是什么形状（流式输出 / token 计量）

- **问题**：模型吐出的那条"河"，代码里怎么接、怎么数、怎么重放？
- **答案链**：原始流是封闭七变体的 **`StreamChunk`** 联合——瞬态只有 delta（可折叠），事实是四件套（block-end / usage / finish / `assistant/attempt`）→ 折叠必须可逆：`expandAssistantStream()` 展不开，计费、追踪、重放全失真 → 适配器只做三件事：wire → StreamChunk、错误 → `LlmFailure`、私有回放 → ReplayEnvelope；组装/重试/计量全在 core → **计量是可重放快照不是计数器**：`TokenMeasurement` 每次 `measure()` 从日志重放，代价 O(surface) → `TokenUsage` 逐调用记账、计数互不重叠——`inputTokens` 只含未缓存输入，缓存单列 → `projectedTokens` 是 last-wins 显示值，不能当准入门槛。
- **现场演示**：拿一份真实会话日志跑展开，数出 chunk 类型分布（收据即统计表）。
- **证据**：ch31、`cheatsheet.md` 流式与计量节。
- **钩子**：模型的手要伸进文件系统——谁拦在中间？→ 沙箱。

#### S2E06（EP12）执行世界：read-only 模式下的 rm -rf（沙箱 / 进程隔离）

- **问题**：受限模式里一条危险命令跑出去，到底发生什么？
- **答案链**：沙箱是 **argv 包装器**，不建进程——`confine(argv, policy, signal)` 返回新 argv + `enforcement` + stderr 分类器；`danger-full-access` 根本不进这套，消费方直接 spawn 原始 argv → `SandboxMode` 只管辖文件效果（read-only 连 `/dev/null` 接收器都要显式授予），网络与进程可见性另立词汇 → 归因三步：runner 失败规则（先剥 `informationalLines` 再精确整行匹配）→ 拒绝签名 → 进程自身失败；"从未运行"与"被拦下"必须分开报 → 拒绝签名是**本后端方言**：bwrap 的 EROFS、Landlock 的 EACCES、Seatbelt 的 EPERM → `enforcement: 'partial'` 是后端报告的事实（旧内核 ABI、Windows ACL 缺口），要绝对边界必须拒绝它 → 会话 cwd 就是 `workspace-write` 边界，Host 搬会话就搬边界；额外可写根 resume/fork 后必须重注册 → 终极戏肉：**SSH 只换提供方，文件系统/子进程/沙箱整个执行世界搬家**，SSH 断线绝不重放可能已执行的操作。
- **现场演示**：本机 read-only 下真跑一条被拒命令，抓 stderr 方言原文与 `SANDBOX_*` 失败码（制作时验证；备胎：方言表上屏 + 既有日志收据）。
- **证据**：ch32（已全文核对）。
- **钩子**：跑过的每一步都要记下来——日志凭什么说"模型可见即已记录"？→ 存储。

#### S2E07（EP13）不会撒谎的日志：熬过崩溃与版本更迭（append-only / 持久化）

- **问题**：为什么敢说"模型可见即已记录"，还敢升级格式不丢老会话？
- **答案链**：`append` 的 resolve ≠ 持久化成功（后端可缓冲），**flush 检查点是唯一"熬过崩溃"的承诺** → 崩溃留痕：先写开始后写结束、锁最后释放，留下有 start 无 end 的可检测遗留；恢复不改文件，在写所有权下把缺失收尾当普通批次追加 → 已提交 generation 不可改名不替换不删除，改写 = 排他发布新代际；版本号只有一个手工真源 `SESSION_FORMAT_VERSION` → 迁移链：每包只管 `vN→vN+1`，复用前一条边的 codec 就错（3→4 不可复用）→ `unknown-state` 后停写、close、重开；手工改小版本戳"回滚"是假象 → 跨请求续传：首传 `afterSeq: -1`，水位只折叠同 session id + 同 generation 的最大 `throughSeq`，允许重复、禁止缺口，fork 从零。
- **现场演示**：打开一份真实 Session 目录的 generations 结构与日志头，逐个字段指认（可行性高）。
- **证据**：ch33、ch13、ch28 投影节、ch39 会话格式节、`patterns.md` 不可变代际与迁移链。
- **钩子**：日志在 Node 进程里，浏览器要用——为什么不能直接 import？→ Remote。

#### S2E08（EP14）两个程序的世界：Host 与 Client 隔空握手（RPC / API 网关）

- **问题**：一份真相在 Node 里，浏览器要用，中间隔着什么？
- **答案链**：Host / Client 是两个独立的 `ts.Program`，根 solution 永不作为种子——普通包只登记进一个 aggregate → 跨界调用只有一条正道：`@Remote` / `@RemoteScope`，**构建期生成严格契约**，参数表禁泛型/可选/解构/默认值/rest → 复杂对象过 wire 靠 wire identity 与 `TypertLookupMap` → 失败面收敛成**一个** `RemoteError` + 码表 `<域>/<理由>`，Client 只判 `code`；无关异常才折 `gateway/internal` → 会话事件流、分页、增量 reduce 不伪装成 Remote，走独立协议 → 改约定必须 `build:lib`，先 Host 后 Client。
- **现场演示**：真调一个 Remote 端点（`cordis_inspect` 本身就是），并故意触发一个带域码的 `RemoteError` 收据。
- **证据**：ch05、ch39、ch07、`cheatsheet.md` 协议与 Remote 节。
- **钩子**：wire 的另一头，浏览器那一半自己怎么长？→ Web 客户端。

### 弧 C · 另一半

#### S2E09（EP15）浏览器那一半：屏幕上的像素归谁管（Web 客户端 / 前端架构）

- **问题**：一个对话页面几十个包往里塞东西，凭什么不乱？
- **答案链**：Web 客户端是**六层所有权**：状态归 Client model、位置归 Slots、跨包行为归注入 service、声明只走 `import type` → 浏览器入口由 **WebBootGraph**（rev / entries / batches）描述，包用 `dsh.client` + `exports["./client"]` 自报家门，缺了组合期就报错 → 挂界面 = `ctx.slots.inject('…', …)` + `ctx.slots.register({ id, order }, Component)`，同一个 dock 多提供方未配 id 抛 `WEB_PROVIDER_AMBIGUOUS` → HMR 页面跟随模块图，启用/禁用插件**不用刷新** → 视觉层纪律：整页是审查单位、1px 发丝线（hairline）、圆角选档制——结构靠线不靠卡片。
- **现场演示**：S1 EP06 的 dock demo 升级版：开发者工具里看 slot 注入顺序与 boot graph（可行性中高，制作时验证）。
- **证据**：ch36、ch14、`frame.md`（本系列自己的视觉规范就是同一哲学的用户）。
- **钩子**：自己的包讲完了——别人写的工具怎么安全地长上这棵树？→ 扩展面。

#### S2E10（EP16）模型的第三方器官：MCP、技能与 LSP（MCP / 扩展系统）

- **问题**：第三方工具接进一棵有纪律的树，边界画在哪？
- **答案链**：扩展面是三元结构、分层注册表、闭合联合 → MCP **一服务器一连接**，工具名带前缀，名字在作用域内唯一；共享服务独立于单个连接 → 动态插件三级身份：Plugin（稳定）/ Package（不可变版本）/ Run（可撤销激活），`stop()` 只停激活、`undefine()` 才真删，跨半调用凭 `pluginRunId` → 多模态五通道：共享服务**只登记名字**，工具与限制归 provider，同名第二次注册必须失败 → 附件准入先于规范化：每消息 ≤20 张、总量 ≤200 MiB、单张 ≤50 MiB；**先持久化后追加事件**，事件只带内容寻址引用 → 失败方向是关闭：无 provider / 无权限 / 被拒都给明确失败，不静默降级。
- **现场演示**：真挂一个 MCP server（本机现成配置即可），收连接与工具前缀收据。
- **证据**：ch34、ch35、`cheatsheet.md` 扩展面节。
- **钩子**：整季都在讲"怎么设计才对"——最后一弧讲"怎么证明自己没坏"。

### 弧 D · 纪律

#### S2E11（EP17）会变红的守卫：AI 改的代码怎么测（e2e 测试 / 测试策略）

- **问题**：一个 agent 大量参与开发的仓库，测试凭什么可信？
- **答案链**：先写命题再选层——七层测试各答一问（局部行为 / 覆盖率 / 真模型对接 / CLI 预期输出 / 基准 / 快照 / 浏览器快照）→ 只 mock 三类昂贵边界：LLM 适配器、网络、时钟，其余全真实 → e2e **验证外部世界**：重跑命令、重读文件、逐字节比对，不做关键词探测——落笔先问"若 agent 撒谎，这条还绿吗？" → 测试真实入口：`bin` 跑构建后的 `lib/bin.js`，暴露 tsx 掩盖的竞态 → 覆盖率按文件 100% 是门禁，未覆盖行优先按**死代码删除** → 回归守卫必须**先制造一次红**：引入回归 → 观察失败 → 回退，两种状态都过的守卫什么也守不住 → CI 强制 `DSH_SNAPSHOT=replay` 只读回放。
- **现场演示**：给一个小包真做一次"引入回归→变红→回退"全程收据（可行性高，也是全季最有行为艺术感的一集）。

#### S2E12（EP18，终章）一概念一个词：118 篇文档怎么不散架（工程文化 / 文档体系）

- **问题**：40 个章节、99 条术语、上百个包——凭什么每一处说的是同一件事？
- **答案链**：一概念一术语：`turn` / `step` / `Round` 三层不可互换，`scope` 扁平两层不向下继承——换词即换概念，这是全库的词汇纪律 → 一个事实一个家：`tier` 划归属层，"不属于此层"也是规则；文档预算三级裁决 Relocate → Condense → Raise，超了先搬再压最后升级裁决 → rescope 只改名：五元组让脚本改名、守七类不变量，改名不改协议 → 评审是堆叠的：每条意见落回**引入它的那层 PR**，修复一 PR 一 commit，改写推送用 rerere + lease、禁 `--force`；失败面 fail-closed：响应没过 schema 整批标不明确 → 收束：把 E01 的接缝、E02 的三域、E03 的可逆、E04–E10 的子系统摆回一张图——纪律不是装饰，是插件树能长到两百个节点还站着的原因。
- **现场演示**：`dsh-internals/` 知识库本身就是证据——40 章由 118 篇蒸馏的产物上屏，同一术语在三章里的定义逐字一致。
- **证据**：ch11、ch12、ch10、ch40。

**每集封面 SOP（嵌在 7.2 第 6 步内）**：

1. **体检**：`python3 scripts/whalegen.py check` 全绿才继续；ComfyUI 没起就 `ssh cyx@100.64.0.8 'schtasks /run /tn ypicture-comfyui'`，约 20 秒后可用。缺 IP-Adapter 时虽可降级出图（`--ipa-weight 0`）但一致性明显下降——**宁可先补环境再开工**。

3. **出图**：`python3 scripts/whalegen.py cover --plan publish/epNN/cover-plan.json --out publish/epNN/cover-base.jpg`——产出 1920×1080、角色靠一侧、对侧压暗留作标题区。默认胸像（`--char-ratio 0.45`：这台机器 1MP 画不好手，胸像让手直接出画，且封面要脸大才扛得住缩略图）；denoise 甜区 0.58–0.65，越界鳍耳发色开始漂。

5. **叠字**：定稿底图进 `publish/cover-overlay.html`——顶部 EP.NN、主标题、唯一蓝词 `<em>`、右列等宽小字，沿用 S1 封面的排字纪律；Chrome headless 截 1920×1080 → `publish/epNN/cover.png`。

\* **口径**：后端只给 `play.rate`（万分比），实测与「平均观看时长 ÷ 时长」六集全部吻合在 ±0.5pp——它的真实含义是**平均播放进度**，不是「看到结尾的人数比例」。页面上的「完播率」列本次未取到（需浏览器会话），**两者不可相减**。S2 只能用同一字段、同一口径。

**基线现实检查（先读这条，再谈阈值）**：六集播放 12–25、收藏 0–2，n=6。这个量级下，单集百分比的一点波动就是一个人——「低于均值 15%」在 EP01 只差 3 次播放，把这种数当决策门，等于用噪声指挥生产。所以判读顺序改为：

1. **主指标看比值与时长**：收藏率、平均观看时长——分母大小不改变形状，能在小样本里看清方向。
2. **完播只作方向**：连续两集同向变化才算信号，单集不下结论。
3. **绝对阈值优先于相对阈值**：用「收藏率 < 4% 连续两集」这类可执行条件，替代「S1 均值 ±15%」。
4. **观察窗 ≥ 7 天**：发布后 72 小时只看明显异常（0 播放、被限流），不进门。

**每集盯三个数**：收藏率（技术内容的真资产：决定长尾检索）、平均观看时长（钩子与答案链是否真的留人）、合集追更（EP07 相对 EP06 = 老观众留存；同样 7 日窗）。
